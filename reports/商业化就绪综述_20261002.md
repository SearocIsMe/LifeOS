## 0. 一页话术（投资说服要点，30 秒版）

**LifeOS 是什么**：AI 陪伴角色的长期身份连续性运行时——身份连续性由外部化状态决定而非模型权重，换模型从「重大事故」降级为「配置变更」。

**三个投资理由**：
1. **技术空白已验证**：「跨模型切换 × 周月级长时程 × 带记忆多会话」的连续性基准与治理运行时，2026-08-05 文献基线查证无人做过（季度重跑守卫）；方法、协议、运行时三层已全部真实交付（254 tests passing，零回归）。
2. **全开源栈零许可成本**：运行时内核、Schema、事件协议、评估基准全开源（无排他性商业 IP），竞争力来源是自有生命 Schema、关系动力学、记忆治理、行为协议与评价体系——开源做获客与标准占位，托管服务/企业支持/专有数据集变现。
3. **合规是出海差异化线**：PIPL（大陆）为主 + 新加坡/香港/澳门多法域合规包 + 两级删除语义 + 敏感项单独同意——面对监管审查的合规前提，与「诱导付费型竞品」的伦理差异线。

**一句话**：工程已收口（阶段 0–3 工程侧全部完成）、伦理已批准、通道已可达——剩余工作是"收数 → 判定 → 产品化立项"的统计执行，技术风险已释放，剩余风险在执行而非设计。

## 1. 实际意义：三层价值主张（从 C 端到 B 端到监管）

### 1.1 C 端：保护用户的情感资产（产品的实际意义）

- 长期陪伴中积累的关系动力学（familiarity/trust/attachment 版本化）与记忆资产（episodic/semantic 记忆 + 双通道召回），在换模型/降成本/国产化替换时**不丢失、不"换人"**；
- H1 真臂证据：30 case / 28 一致（h1_score=0.933 ≥ 90% 门槛，双 vLLM 真模型）——"换模型它还是它"有工程证据（真相源 `phases/phase-1/reports/h1_real_arm_report.json`）。

### 1.2 B 端：规避单一供应商锁死（平台方的实际意义）

- 模型迭代、成本降档、供应商更换时，用户侧体验不变——换模型从「重大事故」降级为「配置变更」；
- 分层路由：≥80% 调用走 Tier-1 本地模型（国产化/固定权重），Tier-2 大模型仅做会话生成与复杂解释——**推理成本结构与供应商议价能力同时改善**（spec §3.4）。

### 1.3 监管侧：红线即代码的合规前提（监管审查的实际意义）

- 10 条 Policy 红线逐条规则 + 每条一个自动化测试用例（高危情感操纵一票否决），面向监管审查的**可审计、可回归**合规证据；
- 两级删除语义 + 30 天备份滚动窗口 + 擦除后三通道不可恢复验证——用户擦除权的机器校验实现（spec §9）。

### 1.4 独立思考：情感资产是双刃剑（路线图未讨论的风险）

- **留存效应**：长期积累的生命 Schema 与关系动力学是天然的 switching cost——用户留存与商业化 LTV 的正资产；
- **监管关注**：情感锁定效应同时是监管审查焦点（尤其未成年人与诱导付费场景）——LifeOS 的红线即代码与敏感项单独同意正是把"伦理负债"转为"合规资产"的设计，但这要求产品化阶段把红线执行从"工程纪律"升级为"产品承诺"（透明披露红线清单），这是路线图没有展开的产品化工作项。

## 3. 部署到应用的前景：三条商业路径

### 3.1 路径 A：基准与协议开源 → 行业标准占位（12–18 个月）

- 开源内容：评估基准（gold set + 八项指标 + H1 协议）+ Life Schema + 事件协议 + 运行时内核；
- 商业逻辑：类似 Chroma/Supabase 路径——基准做引用与获客，协议草案（Life Schema 导出格式）做互操作标准占位；引用基座效应（评测协议具有长引用尾）反哺品牌；
- 前置：盲测数据齐全 → arXiv 系统报告 → 协议草案发布。

### 3.2 路径 B：托管服务 → C 端 companion 载体产品（18–30 个月）

- 载体产品（决策门后另行立项，spec §14）：基于运行时的中文陪伴产品——差异化在连续性治理（不"换人"）与红线透明（不诱导付费）；
- 商业逻辑：会员/增值服务，红线清单透明披露作为信任卖点；单实例月推理成本上限由商业评审设定（margin 见 §4）；
- 前置：Gate 3 通过（盲测门槛 + 无高危操纵 + 成本 P95 达标 + 用户明确感知价值）——**Gate 3 是路径 B 的硬门**。

### 3.3 路径 C：企业支持 → B 端角色连续性基础设施（18–36 个月）

- 企业场景：品牌 IP 角色（游戏/文娱/虚拟主播）的跨模型连续性托管、企业数字员工的角色一致性、国产化替换的连续性迁移支持；
- 商业逻辑：企业支持 + 专有数据集（生命数据模型迁移服务）+ SLA 托管；
- 前置：协议草案发布 + 企业级多实例运维（per-life 串行队列已交付）。

### 3.4 独立思考：路径排序的判断（与路线图阶段门的对应）

- 路径 A 风险最低、时间最快，且是 B/C 的获客前置——**投资的第一阶段回报应锚定路径 A**（盲测数据齐全后 6 个月内可见 arXiv + 协议草案）；
- 路径 B 是消费市场故事，margin 最大化但依赖产品交互界面（研发范围明确不做，需商业化另立团队）；
- 路径 C 是 B2B 现金流故事，但销售周期长——建议 B/C 并行立项、由立项结果决定资源倾斜，不一次性批准（与规格书"按阶段门逐级授权"原则一致）。

## 4. 成本结构与优势：开源零许可 + 分层路由 + margin 留白

### 4.1 成本结构（三类）

| 类 | 结构 | 优势 |
|---|---|---|
| 工程成本 | 研发累计 24–40 人月（阶段 0–3，路线图 §0 工期口径 ±30%） | 已释放大部分技术风险：工程侧全部完成 |
| 推理成本 | 分层路由 ≥80% Tier-1 本地（单 GPU 工作站）+ ≤20% Tier-2 云 API | 单实例月成本结构可控；供应商议价弹性 |
| 合规成本 | 四法域共用一套工程机制（jurisdiction 字段 + 模板版本化 + 最严法域出境策略）；法务确认分批（先大陆后其他） | 边际合规成本低（spec §13） |

### 4.2 成本优势（相对竞品/自研）

1. **零许可成本**：全开源栈（无排他性商业 IP），无 license 与供应商锁定成本；
2. **八项指标回归网**：改一行代码对连续性的影响可量化——没有它，质量事故在用户侧才暴露；这是竞品没有的工程安全网；
3. **分层路由的降档路径**：超限降级先降生成侧模型档位，安全策略与记忆写入链路永不降级——成本弹性与安全底线解耦（spec §3.4）。

### 4.3 margin 范围：有意留白，投资者参与设定（独立思考）

- 规格书明确："单实例月推理成本上限由商业评审设定，本规格不虚构数字；决策门必须给出 P50/P95 实测分布"（spec §1.2/§3.4）——**margin 是投资条款的一部分，不是技术参数**；
- 已有锚点：分层路由比例（80/20）、逐笔成本记录（ModelInvocation）、按 life_id 聚合口径、超限降级路径——margin 设定的数据基础已具备，缺的是**实测 P50/P95 分布**（dogfood 收数后可给）与**定价决策**（投资条款）；
- 独立判断：margin 审查应绑定 Gate 3 判定——P50/P95 实测达标 + 商业评审设定上限，两者齐才启动产品化立项（路径 B/C）。

### 4.4 商业化估算的诚实声明

- 路线图只估算了**研发**人月（24–40 累计）；载体产品、托管服务、企业支持的**商业估算不在路线图内**——本文不虚构数字，诚实声明：路径 A 可复用现有团队（6 个月内可见），路径 B/C 需商业化团队另立估算（产品/UI/运营/销售，需立项后核算）——这是投资者需知的**下一个核算项**。

## 5. 市场针对对象：首发 → 扩展 → 出海

| 阶段 | 对象 | 依据 |
|---|---|---|
| 首发 | 中文社区（大陆为主），中文陪伴产品用户 | spec §1.2（评测语言中文为主、材料锁定）+ §9.6（首发用户群为中文社区） |
| 扩展 | 新加坡/香港/澳门中文用户（均以中文为主要语言之一） | spec §9.4（多法域）+ §9.6（新增法域中文兼容） |
| 出海 | 英文市场（v1 议题，架构无障碍） | spec §9.6（评测材料是版本化数据不是代码，成本在材料与验证不在工程） |

**细分对象**（独立思考，路线图未展开）：
- **C 端**：重视长期陪伴连续性的中文用户（情感资产敏感型），与诱导付费型竞品的用户重叠但诉求不同；
- **B 端品牌角色**：游戏/文娱/虚拟主播的 IP 角色跨模型连续性需求（角色是资产，换模型不能换角色）；
- **B 端企业**：数字员工一致性、国产化替换连续性迁移（Tier-1 本地模型 + 固定权重的合规优势）；
- **开发者**：基准与协议开源后的开发者生态（路径 A 的引用与互操作）。

### 7.2 当前进度定位（独立评估，不完全照搬路线图）

**按路线图四阶段口径**：工程侧 100% 完成（阶段 0/1/2 ✅ + 阶段 3 工程侧 ✅）——但这只覆盖 commercial ready 第一段。

**按 commercial ready 三段口径（本文新增）**：
- 第一段研发收口：**~95%**（Gate 2 调参与部分实测项遗留）；
- 第二段证据与标准：**~40%**（工具链与配置全交付、通道可达；缺公网对接、收数、标注、施测、报告——全部是执行项不是设计项）；
- 第三段商业立项：**~0%**（有意等待 Gate 3 硬门与 margin 条款——不是落后，是纪律）；
- **加权定位**：从研发到 commercial ready 的整体路线中，**处于"工具链就绪 → 统计执行期"的中段（约 55–60%）**——技术风险已释放，剩余是执行与统计风险，流程风险大于技术风险（路线图 §1.0 判断经验证成立）。

### 7.3 独立思考：给研究所合作伙伴的三个决策建议

1. **授权节奏**：按"第二段完成（收数 + Gate 3 判定）→ 第三段立项"的节奏逐级授权，第一阶段资源锚定 M3/M4 执行与文献守卫；不一次性批准第三段；
2. **时间条款**：arXiv 系统报告与协议草案设置"数据齐全后 6 个月"的时间条款（占位价值随时间衰减，空白被占有真实信号）；同时约定"收数 4 周 n<30 触发降级审查"（路线图风险表）；
3. **margin 参与设定**：研究所方应直接参与"单实例月推理成本上限"的设定（这是投资条款不是技术参数），并把 P50/P95 实测分布作为 dogfood 交付的验收项。

## 8. 一句话总结

**LifeOS 的技术先进性有三层真实交付与文献查证守卫、成本结构有全开源栈与分层路由兜底、市场从中文社区起步向多法域出海、合规是差异化线也是护城河；从研发到 commercial ready 整体处于约 55–60% 的"统计执行期"中段——投资的第一阶段回报锚定基准开源与标准占位（6 个月可见），消费与 B2B 立项等待 Gate 3 硬门，研究所方应按里程碑逐级授权并直接参与 margin 设定。**
