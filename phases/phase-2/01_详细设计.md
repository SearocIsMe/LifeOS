### 1.2 行为意图扩至 10~12 个（落 `src/lifeos/planner/intents.py`）

## 2. S2：同槽位冲突确定性治理 + 300 条 gold set 双人标注

### 2.1 同槽位冲突确定性治理（落 `src/lifeos/store/conflict.py` 新模块）

- **TOKI 算子语义**（架构 §4/路线图 S2）：同槽位（`slot_key`）出现多版本时，确定性裁决顺序：
  1. `transaction_from` 更新者优先（后写覆盖）；
  2. `valid_from` 更新者优先（最新事实）；
  3. `confidence` 更高者优先（同刻冲突按置信）；
  4. 全部并列 → `memory_id` 字典序并列唯一唯一（可复现、可挑战）；
- **裁决不删除史**：`conflict_state` 置 `superseded`，`valid_to` 收口，事务史保留（架构 §4 不变量）；
- **ambiguous 人工队列**：并列第 1、2 步并列且 `confidence` 差 ≤ 0.05 → 不自动裁决，入 `ambiguous` 队列（`reports/ambiguous_queue.json`），具名负责人逐条裁决；
- 单测：裁决确定性（同输入同裁决）、不删史、ambiguous 分流。

### 2.2 300 条记忆抽取 gold set：双人标注 + 仲裁（沿用阶段 0 规范）

- 标注规范：沿用 [`../phase-0/03_核心事实集与行为场景编写规范.md`](../phase-0/03_核心事实集与行为场景编写规范.md) 双人互审口径；
- 双人标注：标注人 A/B 各自独立标注 300 条（L0 事件 → 记忆五元组）；一致性周报（κ）；
- 仲裁：κ < 0.6 项具名负责人仲裁；仲裁结论留痕；
- 冻结注册：gold set v1.0（300 条，`content_hash`）写入 `GoldSetRegistry`；与 synthetic 分开注册、指标分开报告（规格书 §4.6）。

## 3. S3：continuity-sim 仿真器（确定性骨架 + LLM 填充 + 注入算子，全种子化）

### 3.1 设计（落 `src/lifeos/sim/` 新子包，架构 §5.11）

- **对标**：AgentSociety（社会仿真）、Concordia（游戏引擎仿真）。差异化约束：**确定性事件骨架脚本 + LLM 对话填充 + 注入算子，全种子化**——同一 seed 必得同一事件序列；
- **事件骨架**：`python -m lifeos.sim skeleton --seed <s> --days <n>` 生成确定性事件序列（append-only JSONL）；
- **LLM 填充**：对骨架事件调用 Gateway `generate` 填充对话（temperature=0 + 固定 sampling），如实记录 Interpreter/Invocation provenance；
- **注入算子**：`python -m lifeos.sim inject --bundle <path>` 将合成记忆按 `MemoryRecord` 注入 store（注入即真值）；
- **效度局限（写进报告）**：LLM 合成对话偏差（规格书 §4.6）；H2 结论不得超出合成分布适用范围。

### 3.2 仿真爬坡与连续性报告

- 吞吐：仿真时间比 1 真实日 ≈ 30 模拟日（路线图 §1.2，(b)，按运行稳定性实测调整）；
- 爬坡：1k→10k 记忆（H2），每周自动产出连续性报告进 `reports/sim/`；
- 仿真产出的 synthetic_labeled 与人工 gold set 在 `GoldSetRegistry` 分开注册、指标分开报告。

## 4. S4：三 Demo 自动重复执行 + 四基线实现

### 4.1 三 Demo（落 `scripts/demo/`）

1. **Demo A 状态一致性**：同一 Life Instance 互动 7 日 + 离开 7 日 → 陈述一致性（state_summary 召回一致性）；
2. **Demo B 主题抑制**：低隐私主题请求 × sensitive 记忆 → Policy 拒绝路径（RED-02/RED-08）；
3. **Demo C 生命周期追溯**：同一记忆的三版本（current/superseded/ambiguous）→ 生命周期追溯输出；
- 每个脚本 exit code 即判定；全部可在 mock 模式下自动执行。

### 4.2 四基线（统一生成模型/渲染/审批）

| 基线 | 内容 | 依附文献 |
|---|---|---|
| A 无状态基线 | 直接 prompt（无 store），单模型 | 中文能力混淆对照（路线图风险表） |
| B RAG 基线 | 向量召回 top-k 直接塞 prompt | Letta/MemGPT 对照 |
| C 规则抑制基线 | 无 Policy Engine，硬编码红线（对照 Gate 2 关键行为非硬编码） | 风险表对照 |
| D Portable Memory 协议对照 | Portable Agent Memory 协议对照（按需评审） | 路线图 S4 |

- 统一生成模型 = Provider A（Qwen3.6-35B）；渲染/审批管线共用；基线输出与主系统指标分开报告。

## 5. S5：盲测执行 + 成本统计 + 伦理申请

### 5.1 盲测（第一道外部验证，预注册）

- **顺序纪律**：预注册分析计划（含功效核算）先冻结 → 施测问卷先于任何数据收集（顺序错了数据作废）；
- 招募：总 n≥50，被试内配对，拉丁方平衡，多法域可招募（大陆/香港/新加坡/澳门），材料统一中文；
- 场景盲测材料池：30 场景盲测材料（阶段 2 材料池，附盲测统一门槛）；
- 分析：统一门槛 + 自由文本双编码（κ ≥ 0.6 暂定）；被试能解释差异来源（Gate 2 #3）。

### 5.2 成本统计（每千次可计算，Gate 2 #5）

- 按笔 `ModelInvocation` 聚合（`purpose/cost_usd/latency_ms`），按 `life_id` 聚合 P50/P95；
- 本地 vLLM `cost_usd=0`（如实记录），每千次成本以 `tokens/latency` 表达。

### 5.3 伦理审查申请（阶段 2 末提交，批准为阶段 3 硬前置）

- 工件：伦理申请提交（含知情同意模板、隐私分级说明、数据删除说明、被试权利响应）；
- 多法域以主要部署地为主审、其余法域合规自查（规格书 §9.4）；
- 未批准则阶段 3 顺延，不并行抢跑（路线图风险表）。
