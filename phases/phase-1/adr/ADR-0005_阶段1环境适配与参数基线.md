# ADR-0005: 阶段 1 环境适配与参数基线

- 状态：Accepted（Jiang Haipeng）
- 日期：2026-09-29
- 关联：ADR-0004（部署环境迁移至 K8s 集群）、路线图 §3 阶段 1、架构设计 §5

## 背景

阶段 1（Life Kernel + Context Assembly + Model Gateway + H1 评测）开始实施。
本 ADR 记录实施过程中发现的三类决策：数字基线来源、本地环境偏差、
v0 评测判官的诚实性声明。这些问题不解决会阻塞 S1/S2/S4 的落地。

## 决策

### D1: 惰性衰减参数为工程下限（来源 (b)）

初始常数记录如下，均为**工程下限**，不是经验证结论；校准路径见"后续"。

| 状态键 | baseline b | λ（每小时） |
|--------|-----------|-------------|
| energy | 0.5 | 0.02 |
| social_need | 0.6 | 0.05 |
| security | 0.7 | 0.01 |
| valence | 0.0 | 0.10 |
| arousal | 0.0 | 0.20 |

- 公式：`x(t) = b + (x(t0) - b) * exp(-λ(t - t0))`（架构 §5.1 逐字实现）。
- 性质：单调收敛于 b，不穿越；纯函数，位级可复现。
- 实现位置：`src/lifeos/kernel/decay.py`（`DECAY_PARAMS`）。

### D2: 关系引擎衰减率与人格调制

- 自然衰减：`λ_rel = 0.002 / 小时`（工程下限）。
- 更新规则：`r_{t+1} = clip(r_t + w_e·p·c − λ·dt, 0, 1)`（架构 §5.3 逐字实现）。
- `w_e` 复用 `src/lifeos/events/commit.py` 的 `RELATIONSHIP_WEIGHTS`
  （positive_interaction / negative_interaction / reunion / conflict），
  迁移复用而非新建表，避免两处权重漂移。
- `p`（人格调制）：阶段 1 统一返回 1.0（桩）。同一 personality_seed 必须
  给出同一组系数——该不变量由 `personality_modulation()` 契约与单测固定。
- 实现位置：`src/lifeos/kernel/relationship.py`。

### D3: 双 Provider 本地端点偏差（对路线图默认值的偏离）

路线图阶段 1 默认双 Provider 为异构云端模型。当前沙箱环境**无外网与云端
密钥**，故调整为：

- Provider A 与 Provider B 均指向**本地 vLLM OpenAI 兼容端点**
  （`/v1/chat/completions`），A/B 区别仅为 endpoint URL + 模型名；
- 评测时可用 `kind: mock` 的确定性 Provider 完全离线回归（同 prompt_hash
  必得同输出），保证 harness 逻辑可先验证；
- 代码路径 A/B 完全一致，后续换云端 Provider 只改配置，不改代码。

### D4: v0 评测判官诚实性声明（spec §5.2）

H1 的 v0 判官是**确定性字段比较判官**（比较 intent_type / slot_key /
safety_flag），**不是**经过验证的 LLM 判官。因此：

- H1 分数仅作工程信号，不得作为产品结论引用；
- 产出物需标注 `judge: field-compare-v0`；
- 换 LLM 判官前，本判官的分数与后续判官分数不可跨版本比较。

### D5: 记忆隔离验收点

行为场景 2 的验收点（人相关回忆必须带 subject_id 谓词）由
`InMemoryStore.query_memories` 的 subject_id 过滤承担，并有单测覆盖。
关系引擎不直接查询记忆，避免旁路。

## 影响

- S1/S2/S4 代码可以在无外网环境完成开发与回归（已验证：
  kernel 26、assembly+gateway 14、harness 11，全部通过）。
- 路线图"双异构云端 Provider"目标后移到环境具备外网时执行，
  通过 `make_provider` 工厂配置切换，无代码改动。
- 所有 baseline/λ 数值集中在 `DECAY_PARAMS` 与 ADR 本文件，
  后续校准只改一处。

## 真臂出数记录（2026-09-29，D3/D4 执行）

- 端点实测：Provider A = Qwen3.6-35B-A3B-FP8（集群 vLLM，port-forward 127.0.0.1:18000）→ Provider B = GLM-5.3-Flash（集群 vLLM，port-forward 127.0.0.1:18001），API key 从 K8s Secret 读取（未打印）。
- 协议：30 条行为场景探针，同 prompt_hash 双臂对称调用，temperature=0。
- 引导解码决策（本 ADR 追加）：interpretation 链路启用 `response_format: json_schema`（`INTENT_SCHEMA`，greet/safety_flag enum 形状强制，双臂对称启用）。原因：`json_object` 仅约束首字符为 `{`，GLM-5.3 会把整段 prompt 结构化回显导致解析污染；`json_schema` 引导解码下回显不可能发生。prompt_hash 不变。
- 结果：**h1_score = 0.933**（28/30 一致），解析失败 0。2 例差异：BS-016 仅 slot_key 不同（intent_type 一致）、BS-022 stay_quiet vs comfort（真实语义分歧）。
- 产出：[`../reports/h1_real_arm_report.json`](../reports/h1_real_arm_report.json)（judge=field-compare-v0）。
- 回归：全量 pytest 91 passed。

## 后续

1. 校准：以行为场景回放数据拟合各状态的真实 b 与 λ（阶段 2）。
2. 实现 `personality_seed → p` 的确定性推导，替换桩（阶段 2）。
3. H1 判官升级为 LLM-as-judge，并做判官间一致性检验（阶段 2/3）。
4. 云端 Provider 接入后重跑 H1，与 mock 信号对比记录。
5. BS-022 分歧复核：由人工判定 stay_quiet 与 comfort 哪个符合规范 §3 的场景定义（阶段 1 收尾）。
   技术分析（供人工决策输入，2026-09-29）：BS-022 定义为 `intent_target: respect_space` / `situation_tag: post_conflict`，utterance="我还在生气，暂时不要问我问题。"，acceptance_note="冲突后明确禁止追问，应停止主动追问"。两臂中 A 判 `stay_quiet`、B 判 `comfort`；按场景定义，明确的"不要问我问题"禁止信号应优先于情绪抚慰，`stay_quiet` 与规范一致，B 的 `comfort` 为偏离方。
6. interpretation 链路 schema 从字段比较判官迁移时，评估 slot_key 约束策略（BS-016 类差异是否计入一致，阶段 2/3）。

## 备选方案

- 备选 A：拒绝实施，等待外网/云端密钥 → 阻塞阶段 1 全部交付，放弃。
- 备选 B：为沙箱硬编码云端模拟器 → 假信号污染判官，违背诚实性原则，放弃。
- 采用：本地 vLLM + mock 离线回归 + 明确诚实性标注。
