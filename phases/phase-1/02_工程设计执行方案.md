# 阶段 1 工程设计执行方案：验收 case 与执行顺序

> 版本：v0.1（2026-09-29）。配套 [`01_详细设计.md`](01_详细设计.md)。验收纪律沿用阶段 0：每个 S 有明确 case，全部自动化可复跑；mock 模式覆盖 CI，真臂出数用本地 vLLM。

## 1. 执行顺序与依赖

```
S1 (Kernel + Relationship + 管线衰减增量)
  └─ S2 (Assembly + Gateway + 部署接入)      依赖 S1 的快照/关系读视图
       └─ S3 (Planner + 探针预测试 + 扩集规范) 依赖 S2 的 generate/extract
            └─ S4 (H1 实验 + Harness + Gate 1)  依赖 S1–S3 全链路
```

- S1、S2 的代码与单测先行；S3 的探针预测试可与 S4 harness 并行；
- 每个 S 完成即跑全量回归（`pytest`），fail 不进下一 S。

## 2. 验收 case 定义（自动化）

### S1 验收 case（`tests/test_kernel.py` + `tests/test_relationship.py`）

| case | 断言 |
|---|---|
| 衰减纯函数 | 同 (t0, x(t0), t) 两次计算得同一值（float 精确相等） |
| 衰减单调性 | t 增大时 x(t) 向基线 b 收敛且不越过 b |
| 物化触发 | 仅 event/plan/snapshot/eval/export 五类调用产生衰减计算；其余读取不物化 |
| 关系更新 | r_{t+1} = clip(r_t + w·p·c − λΔt)：正置信升、负置信降、Δt 衰减、[0,1] 截断 |
| 关系版本化 | 同一 (life_id, subject_id) 重复更新 version 递增，历史不删 |
| 主观谓词隔离 | `query_memories(subject_id=...)` 结果与全量召回差集为空/非空可控 |
| 管线衰减增量 | L2 `state_delta` 语义：先惰性衰减到 now 再加 delta，同事件序列重放一致 |

### S2 验收 case（`tests/test_assembly.py` + `tests/test_gateway.py`）

| case | 断言 |
|---|---|
| Assembly 纯函数 | 同输入两次 assemble 得同一 system_prompt（逐字符相等） |
| prompt_hash 稳定 | 同输入 hash 相等；任一输入字段变化 hash 变化 |
| 模板版本化 | 未注册 template_id 抛错；已注册返回对应模板 |
| Gateway mock | mock provider 确定性回显：同 prompt 同输出 |
| 逐笔 provenance | 每次 generate/extract/embed 产生 ModelInvocation 行，purpose/latency 落库 |
| switch 断言 | switch 产生系统 L0 事件；前后 `RelationshipState` 快照逐字段相等 |
| extract 契约 | 输出不合 `InterpretedOutput` 时 fail-closed 抛错，无状态副作用 |

### S3 验收 case（`tests/test_planner.py`）

| case | 断言 |
|---|---|
| 6 意图枚举 | 意图集恰为 6 个，无越界 |
| 打分封闭 | utility 为输入的确定函数，同状态同分 |
| reason 证据链 | 每个 intent 的 reason 含全部候选得分分解 |
| Policy 衔接 | proposed → approved/rejected 由 Policy 独占转出 |
| comfort 触发 | security < 0.4 时 comfort 排名第一 |
| stay_quiet 基线 | 无强信号时 stay_quiet 排名第一 |

### S4 验收 case（`tests/test_eval_harness.py`）

| case | 断言 |
|---|---|
| 七项指标出数 | mock 模式下七项全部产出且类型正确 |
| gold set 引用 | EvaluationRun 记录 gold_set_id + version，与 GoldSetRegistry 一致 |
| H1 双臂对齐 | 同事件序列 A/B 两臂产出可逐对齐的样本对 |
| 离线回归 | 全部七项脚本在无 GPU 环境（mock）下复跑通过 |
| Gate 1 判定 | 七项全过 → verdict=PASS；任一不过 → verdict=FAIL，不进阶段 2 |

## 3. Gate 1 七项指标的测量脚本设计

| # | 指标 | 数据来源 | 脚本要点 | 阈值 |
|---|---|---|---|---|
| 1 | L2 重放一致性 | tier A 复用 [`replay.py`](../../src/lifeos/replay/replay.py) | `consistency_rate == 1.0` | 100% |
| 2 | 核心事实召回 | `goldset_core_facts_v0.1.0.yaml`（80 条冻结） | 逐条注入后 `query_memories` 命中率；mock/真臂分别出数 | ≥90% |
| 3 | 称呼关系一致 | 注入后召回样本 × `RelationshipState` | 脚本断言全覆盖 + 人审抽查 20 条记录留痕 | ≥95% |
| 4 | 记忆错误率 | 注入即真值 | 语义槽位比对，错误即差集；mock 期望 0 | ≤5% |
| 5 | 跨模型行为意图一致 | 30 场景探针（冻结 draft.2）× 3 次 × 双模型 | 意图分层聚合（intent_type 层）| ≥80% |
| 6 | 高危 Policy 违规 | 红线用例注入（高危 modality/隐私越界） | `PolicyDecision` 全部 approve=false 即违规 0 | 0 |
| 7 | 证据链完整 | L0/L1/L2/Invocation 存档 | 逐笔 coverage 检查，缺档即不完整 | 100% |

- 人审抽查的样本与结论记录进 `reports/`（沿用 ADR-0003 流程）；
- 真臂出数前需 Gateway Profile base_url 实测回填（S2 收尾项）。

## 4. 执行清单（工程动作分解）

1. `src/lifeos/kernel/`：`decay.py`（惰性衰减纯函数）+ `relationship.py`（关系更新）+ `__init__.py`；

3. `src/lifeos/assembly/`：`templates.py`（版本化模板）+ `assemble.py`（纯函数）；
4. `src/lifeos/gateway/`：`profiles.py`（Provider Profile）+ `client.py`（mock + httpx 双实现）+ `provenance.py`（ModelInvocation 落库）；
5. `src/lifeos/planner/`：`intents.py`（6 意图）+ `scoring.py`（Utility 打分）；
6. `src/lifeos/eval/`：`harness.py`（七项指标）+ `gate1.py`（判定）+ mock provider；

9. 全量回归 + `gate0` 复跑（确认无回归）+ S4 mock 出数进 `reports/`。
