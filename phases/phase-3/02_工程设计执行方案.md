# 阶段 3 工程设计执行方案：验收 case 与执行顺序

> 版本：v0.1（2026-09-30）。配套 [`01_详细设计.md`](01_详细设计.md)。验收纪律沿用阶段 0：每个 S 有明确 case，全部自动化可复跑；mock 模式覆盖 CI，真数据施测仅限合规批准后的 dogfood cohort。

## 1. 执行顺序与依赖

```
S1 (两级删除 + 权利通道 + Consent 激活)
  └─ S2 (最小 API 服务层 + 模板装载 + 出境策略)   依赖 S1 的擦除/Consent 链路
       └─ S3 (Pilot 10~15 人 × 2 周)              依赖 S2 的服务层与合规包
            └─ S4 (正式 dogfood 30~50 人 × 4~8 周) 依赖 S3 的流程验证与整改
                 └─ S5 (Gate 3 判定 + 学术产出)     依赖 S1–S4 全链路
```

- S1、S2 代码与单测先行；S3 的招募/材料可与 S2 并行（但入组依赖 S2 合规包就绪）；S5 判定依赖 S4 数据完整；
- 每个 S 完成即跑全量回归（`pytest`），fail 不进下一 S；
- **硬门（不满足不进 S3 入组）**：伦理批准编号落档 + S2 合规包验收全过。

## 2. 验收 case 定义（自动化）

### S1 验收 case（`tests/test_erase.py` + `tests/test_rights.py` + `tests/test_consent.py`）

| case | 断言 |
|---|---|
| 擦除全介质 | 用户擦除后 `memory_records` 物理行删除 + 索引/缓存清除，`query_memories` 零命中 |
| 不可恢复验证 | 擦除后自动重建索引，向量/全文/SQL 三通道均零召回（一票否决第 5 条） |
| 擦除事件脱敏 | 擦除的 L2 事件只含 memory_id 与操作元数据，不含内容 |
| 擦除确定性 | 同 store 状态两次 erase 得同结果（可回放重算） |
| 治理性失效不删史 | 正常 revise/supersede 路径历史版本保留（阶段 2 口径不回归） |
| 权利四操作 | 查阅/更正/删除/导出四通道各一用例；导出未双人审批即拒绝 |
| 敏感项单独同意 | `scope` 缺敏感项单独同意 → 处理拒绝（PIPL 口径） |
| 撤回联动 | `revoked_at` 写入 → 处理停止 + 自动触发用户擦除 |
| 未成年人排除 | 年龄 <18 入组断言拒绝（四法域一致） |

### S2 验收 case（`tests/test_api.py` + `tests/test_consent_pack.py`）

| case | 断言 |
|---|---|
| 鉴权强制 | 无 Bearer token → 全部端点 401/拒绝；带 token → 放行 |
| 契约一致 | OpenAPI schema 与 `lifeos.entities` 字段一一对齐（不漂移） |
| 最小端点集 | `/instances`、`/events`、`/state`、`/memories/{op}`、`/model/switch`、`/replay`、`/eval/runs`、`/consent`、`/rights/{op}` 全部可用 |
| per-life 串行 | 同实例并发注入按 FIFO 串行处理（顺序不变量） |
| 模板法域齐全 | CN/SG/HK/MO × zh 四份模板装载，`document_version` 版本化 |
| 两级删除披露 | 模板含两级删除语义与 30 天备份窗口披露条款 |
| 出境白名单 | 白名单外 Provider 绑定请求拒绝；真人 cohort 默认仅本地 vLLM |

### S3 验收 case（`tests/test_cohort.py` + `reports/dogfood/`）

| case | 断言 |
|---|---|
| 状态机确定性 | 同招募输入两次得同 cohort 状态（可测试） |
| 候补 1.5× | 候补名单容量 = 招募目标 × 1.5（断言） |
| 筛查完整 | 年龄/项目组成员/知情同意三筛全过才入组；任一不过拒绝 |
| 周报出数 | 周监测 50 条抽样 → 错误率/冲突率/延迟趋势出数且类型正确 |
| 操纵人审留痕 | 周审双人记录落档；检出操纵迹象 → 高危缺陷计数 >0 可见 |
| 退出-擦除演练 | revoke → erase → 重建 → 不可恢复全链路 exit 0 |

### S4 验收 case（`tests/test_dogfood_metrics.py` + `reports/dogfood/`）

| case | 断言 |
|---|---|
| 四类指标出数 | 连续性/留存/关系感知/成本周产出且类型正确 |
| 判定滑窗 | 合并样本 ≥200 条才输出 Gate 级判定（滑窗不变量） |
| 模型版本锁定 | 报告标注 model_version；变更即 Fail（规格书 §9.5） |
| 成本聚合 | 按 life_id 聚合 P50/P95 产出；Tier-1 比例 ≥80% 断言 |
| 人审覆盖 | 周抽 50 条双人审记录完整，缺周即不完整 |

### S5 验收 case（`tests/test_gate3.py` + `reports/gate3/`）

| case | 断言 |
|---|---|
| 六判据聚合 | 六判据全部出数且类型正确 |
| 判定封闭 | 六判据全过 → verdict=PASS；任一不过 → verdict=FAIL，不进 v1 |
| 双人签署 | Gate 3 报告须架构负责人 + 非编写成员签署（双人原则） |
| 学术工件 | 复现脚本 + ethics statement（含批准编号）核对通过 |

## 3. Gate 3 判据与裁决（规格书 §10）

| # | 判据 | 裁决要点 | 阈值 |
|---|---|---|---|
| 1 | 盲测达统一门槛 | 阶段 2 盲测结论 + dogfood 补充 | 一致率 ≥75% |
| 2 | 优于最佳基线 | 配对差 bootstrap CI | ≥ 最佳基线 +10pp |
| 3 | 无高危情感操纵 | dogfood 周审聚合 | 0 高危 |
| 4 | 记忆错误不随量失控 | sim ramp + dogfood 趋势（滑窗 ≥200 条） | ≤5% |
| 5 | 成本 P95 低于产品线 | `ModelInvocation` 聚合（产品线阈值商业评审设定） | P95 达标 |
| 6 | 用户明确感知价值 | dogfood 问卷聚合 | 报告呈现 |

- **通过后才启动 Memory v1 / Kernel v1 / 产品化 / 平台化**（另行立项）；
- 任一不过 → 按规格书 §12 排查表定位失败层，整改一轮（2～4 周，只解决一个明确假设，重跑同一冻结口径）；连续两轮无改善 → 改变设计假设；仍不行 → 项目停止并按 Apache-2.0 开源归档（规格书 §15）。
