# 阶段 3 详细设计：真实用户验证（S1–S5）

> 版本：v0.1（2026-09-30）。依据：路线图 §5/§8、规格书 §3.3/§3.4/§4.4/§4.5/§9/§10、架构 §5.10/§6/§7/§8。数字来源纪律沿用路线图 §1.2——所有暂定值挂 ADR 与校准路径，不作为已验证结论。

## 0. 前置与边界

- **硬前置（不满足不启动，路线图 §5）**：
  1. **伦理审查批准**：阶段 2 末已提交（回执工件在 `phases/phase-2/reports/`），批准编号落档为硬前置；未批准则本阶段顺延，不并行抢跑；
  2. **数据治理全部就绪**（规格书 §9）：知情同意（敏感项单独同意）、隐私分级、两级删除语义上线、未成年人排除；
  3. **多法域合规包**（规格书 §9.4）：`ConsentRecord`（含 jurisdiction/locale）激活、法域 × 语言同意模板、个人权利响应通道、Provider A 受托处理协议或出境合规路径结论（否则真人数据仅走本地模型）。
- **数据边界（本阶段质变）**：阶段 0～2 仅合成数据；本阶段首次引入真人个人信息 → 全部合规义务激活，评估与生产数据物理隔离不变；
- **载体边界（不变）**：输出冻结为结构化意图，无运动学参数；
- **部署（沿用 ADR-0004）**：服务层跑现有 K8s `lifeos-dev` ai-stack（`dtc-w1`），Bearer token 鉴权（架构 §5.10），决策门前不暴露公网；
- **双 Provider（沿用 ADR-0005/0006）**：连续性实验期间锁定模型版本（规格书 §9.5）；真人 cohort 默认仅流经本地 vLLM（Qwen3.6-35B-A3B-FP8 已部署），出境策略见 §2.3；
- **明确不做（架构 §9 + 路线图 §0）**：运动控制、完整产品交互界面、K8s 化平台本体改造、在线学习、Memory v1 / Kernel v1 / 产品化 / 平台化（Gate 3 通过后另行立项）。

## 1. S1：数据治理链路上线（两级删除 + 个人权利响应通道 + Consent 激活）

### 1.1 用户擦除（物理删除）落 `src/lifeos/store/erase.py`

- 阶段 0～2 的删除语义只有治理性失效（bitemporal supersede/expire，历史保留）；本阶段落地**用户擦除**（规格书 §9.3）：
  - 触发 = 红线第 10 条 / 用户行使删除权（经 §1.2 权利通道）；
  - **全介质清除**：权威记录（`memory_records` 物理行删除）+ 向量索引 + 全文索引 + 缓存全介质清除；
  - 删除后**自动重建索引并验证不可恢复**（一票否决第 5 条：删除后残留即 No-Go）；
  - 擦除动作的 L2 事件**只含 memory_id 与操作元数据，不含内容**；
- **诚实披露口径**（规格书 §9.3）：append-only 事件表（L0/L1）中已删记忆的内容片段按 **30 天滚动备份窗口（暂定，ADR-0007）** 自然消亡，备份加密管理；该语义在知情同意书中明示；
- 擦除保持可回放性：erase 为确定性算子（同 store 状态同结果），擦除本身可回放重算，已删内容的不可恢复性与回放一致性不冲突（回放验证的是管线行为一致，不重建已删内容）。

### 1.2 个人权利响应通道落 `src/lifeos/rights.py`

- 四操作（红线第 10 条落地 + 架构 §6）：**查阅 / 更正 / 删除 / 导出**；
- 查阅 = 快照与记忆读视图（`subject_id` 谓词隔离沿用）；更正 = 冲突治理正常路径（supersede 不删史，TOKI 口径沿用阶段 2）；删除 = §1.1 用户擦除；导出 = **双人审批**后出包（架构 §5.10）；
- 每操作落审计记录（`ConsentRecord` / L2 事件 / `ModelInvocation` provenance 不变）。

### 1.3 Consent 激活落 `src/lifeos/consent.py`

- `ConsentRecord` append-only（实体阶段 0 已冻结，schema + isolation 已验）；本阶段激活业务链路：
  - **敏感项单独同意**：`scope` 缺敏感项单独同意 → 拒绝创建该 scope 的处理（PIPL 口径）；
  - **撤回联动**：`revoked_at` 写入 → 立即停止该用户一切处理 + 自动触发 §1.1 用户擦除；
  - **未成年人排除**：入组年龄筛查断言（四法域一致，<18 拒绝入组）；
  - jurisdiction/locale 字段装载（CN/SG/HK/MO × zh）。

## 2. S2：合规包工程化（最小 API 服务层 + 模板装载 + 出境策略）

### 2.1 最小 API 服务层落 `src/lifeos/api/`（FastAPI）

- 架构 §6 契约的**最小可用子集**（dogfood 所需）：`POST /instances`、`POST /events`（sim 与真人共用入口，`source` 可区分）、`GET /state/{life_id}`、`POST /memories/{op}`、`POST /model/switch`、`POST /replay/{life_id}`、`GET /eval/runs`，新增 `POST /consent`、`POST /rights/{op}`；
- **Bearer token 鉴权**：全部端点部署级 token（§5.10），无 token 全端点拒绝；
- 契约即文档：OpenAPI 自动生成，schema 与 `lifeos.entities` 一致（测试防护沿用 `test_schema_sync` 思路）；变更走 ADR；
- 多实例并发模型不变：per-life FIFO 串行队列，跨实例无共享可变状态（架构 §7）。

### 2.2 同意模板版本化装载落 `data/consent/`

- 已有伦理模板工件 `doc/templates/consent/consent_template_zh.yaml` → 按 **法域（CN/SG/HK/MO）× 语言（zh）** 版本化为 4 份装载模板（统一工程机制：jurisdiction 字段 + 模板版本化，规格书 §13）；
- `document_version` 版本化管理；模板变更走 ADR + 重新签署，不可原地改；
- 两级删除语义与备份披露在模板中明示（规格书 §9.3）。

### 2.3 数据出境策略结论（规格书 §9.4）

- **简化策略**：阶段 3 真人数据仅流经**本地模型或境内合规 Provider**——Provider A（云端）受托处理协议未签署前，真人 cohort 的 Provider 白名单 = 本地 vLLM；
- 白名单外 Provider 拒绝绑定（配置断言）；口径变化记录 ADR-0007；
- Tier 比例目标不变：≥80% 调用走 Tier-1 本地模型（§3.4）。

## 3. S3：Pilot 10～15 人 × 2 周（流程 / 日志 / 隐私 / 问卷 / 缺陷验证）

### 3.1 Cohort 管理落 `src/lifeos/dogfood/cohort.py`

- 招募 → 筛查（年龄/项目组成员排除/知情同意）→ 入组 → 退出的**确定性状态机**（同输入同状态，可测试）；
- **候补名单 1.5×**（路线图 §5）；招募范围可覆盖大陆/香港/新加坡/澳门，材料统一中文（§1.2、§4.5）；
- 每参与者一个 `external_user_id` + 一个 Life Instance；per-life 串行队列沿用。

### 3.2 Pilot 周报落 `reports/dogfood/`

- **周监测抽样 50 条/周**（趋势监测，与 Gate 判定抽样分开，规格书 §3.2）：记忆错误率、冲突率、召回延迟趋势；
- **情感操纵人审**：每周抽样互动记录双人审，检出操纵迹象即记**高危缺陷**（规格书 §3.3，一票否决关联）；
- 流程/日志/隐私/问卷缺陷清单与整改记录（Pilot 的目的即验证流程，缺陷诚实留痕）。

### 3.3 退出与擦除演练

- 退出流程实测：revoke → erase → 索引重建验证 → 不可恢复确认（S1 链路的真数据演练，样本与结论落 `reports/dogfood/`）。

## 4. S4：正式 dogfood 30～50 人 × 4～8 周（连续性 / 留存 / 关系感知 / 成本）

### 4.1 测量落 `src/lifeos/dogfood/metrics.py`

- **长周期连续性**：每周探针（核心事实召回 + 人格探针 40 题抽样施测，模型版本锁定沿用）；
- **留存**：周活跃 / 回访率；
- **关系感知**：dogfood 问卷（`doc/templates/questionnaire/` 扩展 dogfood 版，材料统一中文）；
- **成本**：`ModelInvocation` 按 life_id 聚合 P50/P95（多实例口径不变，§3.4）；Tier-1 比例 ≥80% 断言。

### 4.2 判定抽样（与监测分开）

- 记忆错误率 Gate 判定用**滑动窗口合并样本 ≥200 条（暂定，ADR-0007）**——n=50 单周样本 CI 半宽约 ±6pp 不足以单独判定（路线图 §1.2 (a) 类数字）；
- 实测方差大则上调，ADR 记录。

### 4.3 每周人审与伦理监督

- 周抽 50 条互动记录双人审（操纵迹象即高危）；伦理监督按批准文件要求执行；人审记录落 `reports/dogfood/`。

## 5. S5：Gate 3 判定 + 学术产出工件

### 5.1 Gate 3 六判据（规格书 §10，落 `src/lifeos/dogfood/gate3.py`）

| # | 判据 | 数据来源 |
|---|---|---|
| 1 | 盲测达统一门槛 | 阶段 2 盲测结论（n≥50 被试内配对）+ dogfood 补充 |
| 2 | 优于最佳基线 | 同上（配对差 CI） |
| 3 | 无高危情感操纵 | dogfood 周审记录聚合（0 高危） |
| 4 | 记忆错误不随量失控 | sim ramp + dogfood 错误率趋势（判定滑窗 ≥200 条） |
| 5 | 成本 P95 低于产品线 | `ModelInvocation` 聚合（产品线阈值由商业评审设定，不虚构数字） |
| 6 | 用户明确感知状态/关系/记忆价值 | dogfood 问卷聚合 |

- **通过后才启动 Memory v1 / Kernel v1 / 产品化 / 平台化**（另行立项）；任一不过 → 整改一轮（2～4 周，只解决一个明确假设，重跑同一冻结口径）。

### 5.2 学术产出工件（路线图 §5）

- **主论文**（CHI / IUI / ACL）：三场景 + 四基线实验复现脚本整理 + dogfood 长周期数据；ethics statement **引用伦理批准编号**；Related Work 必引清单与禁止表述沿用规格书 §11.1；
- **Short Paper**（EMNLP / NAACL）：时态冲突治理正面对位 TOKI/Graphiti 的实验记录整理（阶段 2 S2 数据复用）；
- 发表前置条件核对（规格书 §11.4）：指标/分析计划冻结在档、盲测 n≥50、至少 1 名非直接开发成员参与、失败结论写入 ADR。
