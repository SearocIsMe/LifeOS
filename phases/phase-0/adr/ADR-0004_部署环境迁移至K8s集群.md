# ADR-0004：阶段 0/1 运行环境迁移至 K8s 集群（H200）

- 状态：**Accepted（决策层采纳，2026-09-16）**
- 决策人：项目决策层（Jiang Haipeng）
- 关联：ADR-0002（环境检查记录——本 ADR 触发其重测）、架构设计 v0.9.1 §8（部署架构）、01 文档 §2.2、02 文档 AC-01/AC-02、路线图 §0（算力假设）
- 接收方：新环境工程执行者（含接手智能大模型），交接文档见 [phases/phase-0/HANDOVER_迁移K8s集群交接.md](../HANDOVER_迁移K8s集群交接.md)

## 决策

1. **迁移**：阶段 0 的 Gate 0 环境（及阶段 1 的本地推理部署目标）从「Windows 笔记本 + WSL2 Docker Compose + RTX 4060 Laptop 8GB」迁移至决策层管理的 **K8s GPU 集群**：

   | 目标 | 分工 |
   |---|---|
   | 命名空间 | `lifeos-dev` |
   | 节点 `dtc-w1` | **推理 GPU 节点**：3× H200——阶段 1 S2 的 Provider B（vLLM / llama.cpp）部署目标，模型候选按 H200 显存重新筛选（ADR-0002 候选清单须重做） |
   | 节点 `aisi-w7` | **数据库节点**：PostgreSQL 16 + pgvector 容器（权威数据源） |

2. **docker-compose 降级**：`docker-compose.yml` 不再是 Gate 0 的验收路径，降级为**本地开发备选**（保留在仓库，标注性质）；Gate 0 的 AC-01/AC-02 改为以 K8s 清单为准（`kubectl apply` + 健康等待），验收命令由交接文档 §6 给出。
3. **架构条款顺延**：架构设计 v0.9.1 §8「单机 Docker Compose」条款自本 ADR 起按本决策执行，待架构文档下一版本修订时正式改写（本 ADR 为准）；「多实例共库、per-life 串行队列、单权威源」等不变式**不变**。

## 影响（代码/文档触点，迁移执行者必改）

| 触点 | 变更 |
|---|---|
| `k8s/`（新建） | namespace `lifeos-dev`；postgres（aisi-w7 nodeSelector + PVC + Service）；推理占位 Deployment（dtc-w1，阶段 1 启用）；建议草稿见交接文档 §7 |
| `src/lifeos/store/db.py` | `DEFAULT_DATABASE_URL` 指向集群 Service DNS（如 `postgresql+psycopg://lifeos:…@postgres.lifeos-dev.svc.cluster.local:5432/lifeos`），运行时以 `DATABASE_URL` 注入 |
| `alembic.ini` / `alembic/env.py` | 同上 URL 来源；迁移以集群内 Job 或应用 Pod 执行 |
| `src/lifeos/cli.py` `envcheck` | docker 探测段替换/扩展为 kubectl 段（namespace、节点、Pod 健康、pgvector 扩展、`nvidia-smi`（GPU Pod 内）、Provider key 以集群 Secret 存在性探测） |
| `scripts/gate0_check.sh` | `docker compose up` → `kubectl apply -k k8s/` + `kubectl wait`；`--with-db` 语义不变 |
| `tests/test_db_tier.py` | 依赖 `DATABASE_URL` 可达（集群内 runner 或 port-forward） |
| ADR-0002 | 全部实测字段**作废重测**（新环境）；候选本地模型清单按 H200 重筛 |

## 后果

- 正面：H200（141GB 级显存）解除 8GB 笔记本 GPU 的候选模型瓶颈；推理与数据库资源分离，为阶段 1 S2（本地推理是最大工作量项）铺路；
- 代价：环境复杂度上升（镜像仓库、存储类、Secret 管理）；**已完成的 Gate 0 结论需在新环境复测后才可引用**（工程断言与环境相关部分：迁移、隔离、回放——纯函数断言仍有效）；
- 注册纪律不变：gold set v0.1.0 已冻结，迁移不触碰其内容；评测与生产数据物理隔离原则在集群上继续成立（namespace 隔离是必要非充分条件，阶段 3 合规评审时复核）。
