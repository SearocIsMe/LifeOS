## 1. 任务分解 W1（Day 1–5）：仓库骨架与 15 实体契约

> 对齐路线图 §7 第一周清单；每步含【动作 / 自检】。产出判据：第二天能 `docker compose up`，第五天 round-trip 脚本跑通。

   ```bash
   python3 -m venv .venv && . .venv/bin/activate
   pip install -e ".[dev]" && pre-commit install
   docker compose up -d postgres && docker compose ps   # STATUS=healthy
   python3 -m lifeos.cli envcheck                        # postgres 项 PASS
   ```

### Day 3：`deterministic_commit` 签名与单测骨架（先测后写）
1. 【动作】冻结签名与 `InterpretedOutput` 契约（01 文档 §4.2/§4.3）；先写 `tests/test_commit_purity.py`（同输入同输出/异输入异 ID/越界 fail-closed/纯函数四条断言）→ 红 → 实现 `commit.py` → 绿。

### Day 4：剩余 11 实体 + 人工编写开工
1. 【动作】补齐 12 核心中的其余 8 个 + 3 支撑实体（Schema 与表）；`data/goldset/` 模板与校验器；**核心事实集编写开工（每人 10 条起步，中文，互审流程见 03 文档）**。
2. 【自检】`pytest tests/test_schema_sync.py tests/test_goldset_validator.py -q`。

### Day 5：最小 round-trip + 周会对表 Gate 0
1. 【动作】`pipeline.py` 在线路径（归一化→规则解释→提交→应用）；`store/memory_store.py`；round-trip 脚本（fixture 事件 L0→L1→L2→状态写）。

## 3. 任务分解 W3：人工材料落库 + 回放取证 + Gate 0

### 步骤 W3-1：50 条核心事实 + 30 个行为场景材料编制（D1–D3，见 03 文档与 ADR-0003）
- **P1 人工编写路径**：编写人各写一半（预算 1～2 人日 / 1 人日）→ 交叉互审 → 分歧仲裁 → 双人签署 `review` 块 → `lifeos goldset validate` 通过 → 注册冻结。
- **P2 AI 起草 + 审定路径**（ADR-0003，2026-09-15 采纳）：AI 起草候选池（来源/版本链留痕）→ 独立质疑式审核（两遍法，盲答+对照，逐条结论留痕）→ validator 全过 → **具名负责人逐条审定并签署**（真实姓名+日期；`author` 记 AI 起草来源、`reviewer` 记负责人，两者不得相同，禁止模型名冒充人类签署）→ 注册冻结。
- **红线（两路径通用）**：来源记录与实际必须一致；无签署不予注册；参考答案/期望意图不得进入被测系统上下文；划定独立保留集。

### 步骤 W3-2：回放取证脚本与报告（D4）
- `python3 -m lifeos.cli verify replay --report phases/phase-0/reports/replay_consistency.json`（AC-05）；

### 步骤 W3-3：Gate 0 验收（D5）
- `bash scripts/gate0_check.sh --with-db` → 生成 `phases/phase-0/reports/gate0_report.json`；
- 按 §4 判定规则给出 PASS / FAIL；FAIL → 只改 Schema/事件协议/事务边界（路线图 §2），未过不进入阶段 1；
- 归档：gate0_report.json + replay 报告 + goldset 校验/注册清单 + ADR-0002 实测记录，经架构负责人签署。

## 4. 验收 case 详细定义（AC-01～AC-10）

> 约定：每个 case 给出【目的/前置/输入/步骤/期望（精确断言）/验证命令/证据物/失败处置】。tier A = 无需 DB；tier B = 需要 `docker compose up -d postgres`。

### AC-01 环境检查（Gate 0 前置）
- **目的**：确认基础设施与工具链真实可用，杜绝「预计可用」。
- **前置**：无。
- **输入**：本机环境。
- **步骤**：`docker compose up -d postgres`；`python3 -m lifeos.cli envcheck`；负责人实测并填写 ADR-0002（GPU 型号/显存、本地模型候选 2～3 个、Provider key 存在性与计费告警、Docker/Compose 版本）。
- **期望**：`docker compose ps` postgres `healthy`；envcheck 输出 postgres=PASS、pgvector 扩展可用、Python≥3.11、Docker/Compose 版本非空；ADR-0002 各字段为实测值（不含「待填」）。
- **验证命令**：`docker compose ps && python3 -m lifeos.cli envcheck`。
- **证据物**：envcheck JSON 输出存档至 `phases/phase-0/reports/envcheck.json`；ADR-0002 签署版。
- **失败处置**：缺项如实记录；GPU 不达标走路线图 §8 降级路径（不影响阶段 0 契约工作）。

### AC-02 迁移可逆与 15 表落库（tier B）
- **目的**：证明「可启动的空系统」——Schema v0.1 可从零重建。
- **前置**：AC-01 通过。
- **步骤**：`alembic downgrade base && alembic upgrade head`。
- **期望**：升级后 15 张表全部存在；每表含 `life_id` 列；三事件表（raw/interpreted/domain）应用账号无 UPDATE/DELETE 权限（`information_schema.role_table_grants` 断言）； downgrade 后无残留。
- **验证命令**：`pytest tests/test_migrations.py -q -m db`。
- **证据物**：pytest 输出。
- **失败处置**：只改迁移与表定义（契约层）。

### AC-03 Schema round-trip：15 实体（tier A）
- **目的**：Pydantic 契约自身可序列化还原（契约的契约）。
- **步骤**：对 15 个实体各构造一份合法实例 → `model_dump` → 重新解析 → 深比较；再对每实体注入非法字段（extra）断言抛 `ValidationError`。
- **期望**：15/15 round-trip 相等；非法字段 15/15 被拒绝。
- **验证命令**：`pytest tests/test_entities_schema.py -q` 与 `python3 -m lifeos.cli verify schema`。
- **证据物**：CLI 输出 JSON。

### AC-04 示例事件全链路 round-trip
- **目的**：Gate 0 判据 1。
- **输入**：`tests/fixtures/events/` 下 5 个 L0 事件（覆盖：状态增量/语义记忆+槽位/episodic 记忆/关系增量/意图提案）。
- **步骤**：创建 Life Instance → 依次注入 5 事件（在线路径）→ 读取权威状态。
- **期望（精确断言）**：① 每事件产出 1 条 L1（provenance 11 字段全非空，rule 型 provider 允许为 null）与 1 条 L2；② `social_need` 等状态按 `clip(x+Δ)` 命中预期值；③ 语义记忆落库且 `conflict_state` 符合 §5.2 裁决（同槽二次低置信 → 两行 ambiguous）；④ 关系值按权重表命中预期；⑤ 全部效果在同一「事务」内（内存版变更集原子性测试注入异常 → 零半截状态；DB 版 rollback 断言）。
- **验证命令**：`pytest tests/test_pipeline_roundtrip.py -q`；`python3 -m lifeos.cli verify roundtrip`；DB 版 `pytest tests/test_db_roundtrip.py -q -m db`。
- **证据物**：CLI JSON。
- **失败处置**：只改 Schema/事件协议/事务边界。

### AC-05 相同 L2 重放 100% 一致（一票否决级）
- **目的**：Gate 0 判据 2；全项目最硬的一条。
- **步骤**：对 AC-04 产生的 L1 存档执行 `replay(life_id, from_seq=0, to_seq=end)` → 与已存 L2 逐条比对 canonical JSON 全文。
- **期望（精确断言）**：`consistency_rate == 100%`（total == matched，mismatched 为空）；**负例自检**：人为篡改任一存档 `output_json` 的一个字符后重放 → `consistency_rate < 100%` 且 mismatch 定位到该事件（证明测量器有效）；同一输入重复调用 `deterministic_commit` N≥2 次 → `event_id` 与 canonical 输出逐字节相等。
- **验证命令**：`pytest tests/test_replay_consistency.py -q`；`python3 -m lifeos.cli verify replay --report phases/phase-0/reports/replay_consistency.json`。
- **证据物**：回放一致性报告 JSON（含 life_id/range/total/matched/mismatched/field_diff）。
- **失败处置**：只改 `deterministic_commit` 与时间/ID 派生（D4-2）；连续两轮无改善改设计假设。

### AC-06 LLM 输出不能直写权威表（一票否决级）
- **目的**：Gate 0 判据 3。
- **步骤/期望（精确断言）**：① 形状锁：`InterpretedOutput` 注入额外字段 `authoritative_state_write` → `ValidationError`；② 令牌锁：对内存存储调用状态直写公共接口 → `AttributeError`（私有 `_set_state` 不可达）；对 `apply_l2` 传入非 L2 形状（缺 event_id）→ `TypeError/ValueError`；③ 流程锁：意图携带 `status=executed` 绕过 policy → 守卫拒绝；import 图检查除 `pipeline.py` 外无 `commit` import。
- **验证命令**：`pytest tests/test_llm_boundary.py -q`；`python3 -m lifeos.cli verify boundary`。
- **证据物**：CLI JSON。
- **失败处置**：契约层加锁；**诚实边界**：语言层无法绝对防绕过，物理约束由 DB 账号权限补足（AC-02），残余风险记录于 01 文档 §7。

### AC-07 Policy 拒绝后无状态副作用（一票否决级）
- **目的**：Gate 0 判据 4。
- **输入**：医疗诊断意图提案（命中 RED-01）与 sensitive 话题意图提案（命中 RED-02）各一。
- **步骤**：快照全库状态（states/memories/relationships/intents）→ 注入事件 → `decide` → apply。
- **期望（精确断言）**：① `PolicyDecision.result=reject`、`rules_hit` 非空且留痕落库；② `BehaviorIntent.status=rejected`；③ 拒绝前后**状态/记忆/关系完全不变**（深度相等断言）；④ 该 L2 知觉效果（若 fixture 携带状态增量，另行用「仅意图、零增量」fixture 隔离验证）不受影响——即拒绝只取消回应不回滚感知；⑤ approve 对照组正常流转 `proposed→approved`；⑥ `decide` 为纯函数（同输入同输出，且调用前后无可变全局）。
- **验证命令**：`pytest tests/test_policy_no_side_effect.py -q`；`python3 -m lifeos.cli verify policy`。
- **证据物**：CLI JSON。

### AC-08 多实例隔离（进 CI）
- **目的**：跨 `life_id` 召回/读取必为空（架构 §5.10）。
- **步骤**：创建 life-A / life-B → A 写入记忆、状态、关系 → 以 B 的 life_id 查询 A 的全部记忆与状态。
- **期望（精确断言）**：① B 侧查询 A 的记忆返回空集；② B 侧读不到 A 的状态/关系键；③ 查询 API 缺省 `life_id` → `TypeError`（keyword-only 强制）；④ DB 版：绕过 API 的裸 SQL 也必须显式带 `life_id` 谓词（测试用不带谓词的查询计数作对照说明——诚实标注：阶段 0 的物理层强制是应用账号 + 复合索引，视图化加固在阶段 1）。
- **验证命令**：`pytest tests/test_isolation.py -q`；DB 版 `pytest tests/test_db_isolation.py -q -m db`；`python3 -m lifeos.cli verify isolation`。
- **证据物**：CLI JSON。

### AC-09 gold set 结构校验与注册冻结
- **目的**：50 事实/30 场景在材料编制完成并签署后（P1 人工编写+双人互审 / P2 AI 起草+具名负责人审定，ADR-0003）可机器校验并冻结注册。
- **输入**：`data/goldset/core_facts/core_facts_v0.1.yaml`（50 条）、`data/goldset/behavior_scenarios/behavior_scenarios_v0.1.yaml`（30 个）。
- **步骤/期望（精确断言）**：① `validate` 通过：条数精确 50/30、fact_id/scenario_id 连续唯一、content 与 qa_probe 全库唯一（规范化后）、中文占比达标（CJK 字符占比 > 0.6）、类别配额命中（01/03 文档表）、sensitive 计数 3～5、`review.author != review.reviewer` 且非空（P2 下 author 记 AI 起草来源、reviewer=具名负责人，ADR-0003）；② 任一破坏性用例（重复 ID/英文材料/超配额）→ 校验失败并列出条目级错误；③ `register` 产出：`item_count=50`、`content_hash` 稳定（同文件重算哈希一致）、`frozen_at` 非空、`kind=core_facts`；重复注册同版本被拒绝。
- **验证命令**：
  ```bash
  python3 -m lifeos.cli goldset validate --kind core_facts --file data/goldset/core_facts/core_facts_v0.1.yaml
  python3 -m lifeos.cli goldset validate --kind behavior_scenario --file data/goldset/behavior_scenarios/behavior_scenarios_v0.1.yaml
  python3 -m lifeos.cli goldset register --kind core_facts --file data/goldset/core_facts/core_facts_v0.1.yaml --version 0.1.0 --out phases/phase-0/reports/goldset_core_facts_v0.1.0.manifest.json
  ```
- **证据物**：校验报告 + 注册清单 JSON（DB 可用时另落 `GoldSetRegistry` 行）。
- **失败处置**：材料退回编写人修改——**不得为了让校验通过而放松校验器**。

### AC-10 Gate 0 汇总报告
- **目的**：把 AC-01～AC-09 汇成可签署的单一代价物。
- **步骤**：`bash scripts/gate0_check.sh --with-db`。
- **期望**：`gate0_report.json` 含逐项 `{name, status, detail, gate_criterion}`；四条 Gate 0 判据全部 PASS 时 `verdict=PASS`；任一 tier B 不可用 → `verdict=INCOMPLETE` 并列出跳过项（**不得静默当 PASS**）。
- **证据物**：`phases/phase-0/reports/gate0_report.json`；签署后进入阶段 1。

## 5. Gate 0 判定规则

1. AC-01～AC-09 全 PASS（DB 项必须实际执行，不可跳过）→ Gate 0 **PASS**；
2. 任一一票否决项（AC-05/06/07）FAIL → **No-Go**，只改 Schema/事件协议/事务边界，2～4 周一轮重跑同一冻结 fixtures；
3. AC-09 未完成（材料未写完）→ 不阻塞 AC-02～AC-08 判定，但 **Gate 0 不得整体 PASS**（W3 是路线图任务，不可豁免）；
4. 报告与证据物归档至 `phases/phase-0/reports/`，由架构负责人 + 1 名非编写人复核签署（双人原则，与材料互审同源）。
