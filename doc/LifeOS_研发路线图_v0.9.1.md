## 0. 资源与边界假设（显式声明，非承诺）

以下假设来自规格书与决策层确认，任一变化须重排本路线图：

- **团队**：阶段 0～1 按 2～3 人计（1 架构负责人 0.5 FTE + 1～2 Python/AI 工程师 + 1 后端/DB 工程师）；
- **算力**：本地推理（Provider B）按单 GPU 工作站最低配置规划，Gate 0 环境检查时确认；云端大模型按 API 计费；
- **范围**：不做运动控制、不做产品交互界面（规格书 §1.1）；
- **已确认边界参数（规格书 §1.2）**：
  - 评测语言：**中文为主**，全部评测材料中文编写并锁定；英文为决策门后的 v1 议题（规格书 §9.6）；
  - 部署形态：**单机多实例**共库，per-life 串行队列；
  - 合规管辖区：**多法域**——中国大陆（PIPL）为主，扩展覆盖新加坡（PDPA）、香港（PDPO）、澳门（第 8/2005 号法律）；合规义务自阶段 3 起（规格书 §9.4）；
  - 盲测口径：**总样本 n≥50 下限、被试内配对**，预注册功效核算；
  - 文献基线：`adadmic_innovation_v0.9.1.md`（文献调研日期 2026-08-05），季度重跑检索式；
- **工期口径**：人月为工程中位估算，误差 ±30%。

## 1. 总体策略

### 1.0 先证最危险的假设，先打通平台

三条假设的危险度排序：**H1（身份连续可工程化）> H2（记忆可信）> H3（用户可感知）**。H1 是全部价值的地基——如果换模型就「换人」且修不好，后面都不必做。因此：

- **研究切入点 = H1 的最小实验**（场景三「换模型它还是它」的雏形），而不是先把平台做全；
- **工程切入点 = 契约先行**（Schema + 事件协议 + 回放）——这是后续一切的地基，也是最容易动手的部分（纯数据建模，无 ML 不确定性）；
- **执行顺序（v0.9.1 明确）**：`infra 骨架（阶段 0）→ 最小数据打通平台（阶段 1）→ 数据规模化构造（阶段 2）→ 真人外部验证（阶段 3）`——先让平台在最小数据上端到端跑通，再投入大规模数据构造，避免「数据等平台」或「平台等数据」的空转；
- 每个阶段都能独立停止，Gate 未过不进入下一阶段。

动手难易度总览（★越多越难，难点在不确定性而非工作量）：

| 阶段 | 难易度 | 主要不确定性 |
|---|---|---|
| 0 契约与骨架 | ★ | 几乎无，纯工程 |
| 1 跨模型连续性 | ★★★ | Context Assembly 能否撑起 ≥90% 召回（H1 核心风险）；两模型中文能力差异的混淆控制 |
| 2 三 Demo + 基线 | ★★ | 盲测组织与统计执行（流程风险大于技术风险）；仿真器效度 |
| 3 真实用户验证 | ★★★★ | 招募、多法域合规、伦理审批、长周期运维 |

### 1.1 数据流与验证对象总览（v0.9.1 新增）

每个阶段回答五个问题：**输入什么数据 → 平台打通到什么程度 → 系统输出什么数据 → 谁来验证 → 验证结论对谁有效**。验证对象从「自己」逐步外推到「外部被试」再到「真实用户」——这是证据等级的递进，**阶段 1 的指标再好也不构成用户感知证据**（避免自我验证循环）。

| 阶段 | 输入数据（来源） | 平台打通目标 | 系统输出数据 | 验证对象（谁来验） | 结论对谁有效 |
|---|---|---|---|---|---|
| **0 契约与骨架** | 50 条核心事实 + 30 个行为场景（**人工中文编写**，2 人 × 数日，唯一非自动化输入） | 事件管线 round-trip、回放取证、Policy 审批流 | Schema、事件流、回放一致性报告 | **自动化断言（CI）+ 开发团队互审**（50 条事实与 30 场景双人互审） | 工程团队内部 |
| **1 跨模型连续性** | 核心事实扩至 100 条；40 题人格探针（预测试后冻结）；双 Provider（云端 API + 本地推理） | 端到端对话全链路（状态→记忆→规划→审批→渲染→写回） | Gate 1 七项指标数据 + H1 实验记录 + 两模型中文能力基线 | **Eval Harness 自动断言（对照冻结 gold set）+ 团队内人审**（称呼/错误率周抽 50 条） | 工程团队内部（可支撑内部 Go/No-Go，不构成对外声明） |
| **2 三 Demo + 基线** | 300 条记忆抽取 gold set（**双人标注 + 仲裁**）；continuity-sim 合成数据（注入即真值）；30 场景盲测材料池 | 平台规模化 + 仿真爬坡（1k→10k 记忆）+ 四基线对照 | Gate 2 指标 + 盲测数据集 + 成本 P50/P95 + 合成标注材料（synthetic_labeled） | **三层**：①合成标注（构造即真值，自动验）；②300 条 gold set 双人标注一致性（κ 周报）；③**外部被试盲测 n≥50（第一道外部验证，预注册）** | 外部被试（受控实验条件下） |
| **3 真实用户** | 真人 dogfood 交互数据（多法域合规下，Pilot 10～15 人 → 正式 30～50 人） | 产品化前验证（留存/运维/合规全链路） | 长周期连续性/留存/关系感知/成本数据 | **真实用户**（使用中验证）+ 每周人审 + 伦理监督 | 真实用户（生态效度最高） |

**数据构造与 gold set 的排期原则**：gold set 是「量尺」，必须**先于或同步于**被测功能冻结（顺序错了数据作废）；continuity-sim 是「数据源」，在平台打通后（阶段 2）才投入规模化。仿真产出的合成标注材料与人工 gold set 在 GoldSetRegistry 分开注册、指标分开报告（规格书 §4.6）。

### 1.2 量化数字的来源与校准说明（v0.9.1 新增）

**诚实分类**：本路线图与规格书中的全部量化数字只有三种来源——**(a) 统计功效推算**（可复核）、**(b) 覆盖/预算驱动的工程地板**（承认是启发式而非科学结论）、**(c) 文献/学界惯例引用**（标注出处）。没有任何数字是「拍脑袋后不可挑战」的——每个都挂了校准路径，阶段 1 校准一次、决策门前冻结。

| 数字 | 当前值 | 来源类别 | 来源与理由 | 校准路径 |
|---|---|---|---|---|
| 核心事实集 | 阶段 0 建 50 条 → 阶段 1 扩至 100 条 | (b) + (a) | 50 = 阶段 0 预算内的人工编写量（约 1～2 人日，双人互审）；扩至 100 = 使 ≥90% 阈值具备统计分辨力（n=100、p=90% 时二项 CI 半宽约 ±6pp，可区分 90% 与 ~84% 的真实水平） | 仅当 §12 排查表明失败源于事实覆盖不足时再扩；扩须重跑全部回归测试 |
| 行为场景 | 30 个 | (b) | **覆盖驱动的地板，非统计功效驱动**：6～12 个意图 × 关键状态组合（低能量/高依恋/冲突后等）的最小覆盖。诚实声明：30 个探针在 80% 阈值上功效偏弱（CI 半宽约 ±14pp） | 判读按**意图分层聚合 + 每场景重复 3 次施测**（v0.9.1 已写入规格书 §3.2）；必要时扩至 60 个 |
| 人格探针 | 40 题 | (b) + (c) | 五维大五 × 8 题/维的均衡设计（改编简版问卷的通行做法） | 预测试（α/重测信度）不达标先修题再冻结；题目分配按实际信度调平 |
| 记忆抽取 gold set | ≥300 条 | (b) + (a) | 300 条 ≈ 双人标注 + 仲裁的预算上限（约 2～3 人周）；300 条足以稳定估计抽取错误率（5% 量级时 CI 半宽约 ±4pp） | H2 主战场，扩充优先级最高 |
| Cronbach α ≥ 0.7 | 暂定阈值 | (c) | 心理测量学通行经验法则（常引 Nunnally 1978 提出的 0.7 惯例，学界标准做法），**非本项目实证** | 阶段 1 S3 预测试后按实测分布校准；若探针短（40 题）导致 α 偏低，可按维度分层报告 |
| 同模型重测信度 r ≥ 0.7 | 暂定阈值 | (c) | 同上，重测信度的通行惯例阈值 | 同上 |
| 记忆错误率判定滑窗 | ≥200 条 | (a) | n=200、p=5% 时 CI 半宽约 ±3pp，可支撑 ≤5% 判定；n=50 时 ±6pp 不足以判定（故区分监测抽样与判定抽样） | 预注册时冻结；实测方差大则上调 |
| 盲测 n≥50 | 总样本下限 | (a) | 被试内配对下检测 +10pp 配对差的常用最低规模量级；被试内设计使每臂获得 n≥50 份判断 | 预注册时按预期效应 + 组内相关做功效核算，不足扩至 ≤100（ADR） |
| 仿真时间比 1 真实日 ≈ 30 模拟日 | 目标值 | (b) | 工程吞吐考量：使「互动 7 + 离开 7」的模拟实验在约 0.5 个真实日内完成，支持周级迭代 | 按运行稳定性实测调整，ADR 记录 |
| 行为意图 6～12 个 | 阶段 1：6 个；阶段 2：10～12 个 | (b) | 最小可用集（覆盖 energy/social/security 状态 × 关系冷暖的基本组合）；上限受 Policy 红线测试用例的覆盖成本约束 | 意图增减走 ADR + 注册表 |
| Gate 0 期 50 条/30 场景的编写预算 | 1～2 人日 / 1 人日 | (b) | 按每人每天 20～30 条高质量中文事实/场景的保守产出率估算 | 首周实测产出率后修正 |

**一句话**：统计可推导的标了 (a)，工程地板的标了 (b) 并承认是启发式，引用惯例的标了 (c) 并给出出处——这是本路线图对「数字从哪来」的完整交代。

## 2. 阶段 0：契约与可重放骨架（3 周，2 人，1～2 人月）

**为什么从这里开始**：它是唯一「做对做错立刻知道」的阶段——回放一致率要么 100% 要么不是，没有模糊地带；且全部后续工作都建立在这份契约上。

**输入**：

- 规格书 v0.9.1 §3/§5/§6（功能与模块概述）、§1.3（判定框架）、§1.4（职能表）；
- 架构设计 v0.9.1 §3（事件模型）、§4（15 实体字段表）、§5.10（安全运维基线）；
- 文献：ActiveGraph（arXiv 2605.21997）与 ESAA（arXiv 2602.23193）——参考其 append-only 日志与意图/提交分离的具体实现，避免踩坑。

**任务分解（按周）**：

| 周 | 任务 | 输出 |
|---|---|---|
| W1 | 仓库与 CI 骨架；PostgreSQL+pgvector Docker Compose；15 实体 Pydantic Schema（12 核心 + 3 支撑）+ Alembic 迁移 | 可启动的空系统；Schema v0.1 |
| W2 | L0/L1/L2 事件协议 + `deterministic_commit` 函数（在线/回放同一路径）；Policy Engine 最小骨架（2 条红线先跑通审批流） | 事件管线 round-trip |
| W3 | 50 条核心事实集 + 30 个行为场景落库（**人工中文编写，双人互审**——本阶段唯一的「数据构造」，见 §1.1 表）并注册 GoldSetRegistry；回放取证脚本；Gate 0 验收 | Gate 0 报告 |

**动手提示**：

- W1 没有任何研究成分，目标是第二天就能 `docker compose up`；
- `deterministic_commit` 是全局最关键的函数，先写它的纯函数签名再写任何存储代码；
- 50 条核心事实集是**人工编写**的，别试图用 LLM 生成——它是后续所有测量的标尺；
- 多实例隔离从第一天就做对：所有 SQL 谓词强制带 `life_id`（后补成本远高于先做）。

**环境检查项（Gate 0 前置）**：GPU 工作站可用性（型号/显存记录入 ADR）+ **候选本地模型清单（按显存筛选 2～3 个候选，记录入 ADR）**；云端 Provider API key 与计费告警（优先境内可合规使用的服务，规格书 §9.4）；Docker/Podman 版本。

**Gate 0（规格书 §10）**：示例事件全链路 round-trip；相同 L2 重放 100% 一致；LLM 输出不能直写权威表；Policy 拒绝后无状态副作用。**未通过：只改 Schema/事件协议/事务边界，不继续做 UI 与 Demo。**

## 3. 阶段 1：最小数据打通平台 + 跨模型连续性验证（6～8 周，2～3 人，新增 5～8 人月，累计 6～10）

**研究切入点（本阶段唯一的研究目标）**：H1 最小实验——

> 同一 Life Instance，相同结构化状态，Provider A（云端）→ Provider B（本地），核心事实召回能否 ≥90%？

这是全项目**单位投入信息量最大**的实验：通过则 H1 有工程证据，主论文论点成立一半；不通过则第 4 周就知道，整改成本最低。**本阶段同时是「平台在最小数据上端到端跑通」的阶段**（§1.1）。

**输入**：

- 阶段 0 的契约与骨架（50 条事实 + 30 场景已就位）；
- 文献：Portable Agent Memory（arXiv 2605.11032，状态迁移协议参考）、SPASM（arXiv 2604.09212，外部表示重注入参考）、PICon（arXiv 2603.25620，一致性测量方法）；
- 本地推理最低配置确认（Gate 0 环境检查项的闭环）。

**任务分解（按双周）**：

| 双周 | 任务 | 输出 |
|---|---|---|
| S1 | Life Kernel（3 状态惰性衰减）+ Relationship Engine（有界规则）；Memory OS 写入管线（含 EmbeddingOutbox） | 状态可更新、记忆可写入 |
| S2 | Context Assembly 纯函数 + Model Gateway 双 Provider（实例级绑定）+ 本地推理部署（vLLM/llama.cpp，1～2 人月大头在此） | 双模型可切换 |
| S3 | Behavior Planner（6 意图 Utility Scoring）+ Gradio 调试台最小版；核心事实集扩至 100 条；人格探针预测试（α ≥ 0.7、重测 r ≥ 0.7，暂定阈值，来源见 §1.2 表）达标后冻结 40 题中文问卷；记忆抽取 gold set 300 条标注启动（标注规范 + 试标） | 端到端可对话；探针冻结；标注启动 |
| S4 | **H1 最小实验**：场景三雏形跑通，八项指标中的 6 项出数；两模型中文通用能力基线测量（混淆控制）；Gate 1 验收 | Gate 1 报告 + H1 实验记录 |

**动手提示**：

- 本地推理部署是全阶段最大工作量项，**第一周就并行启动**环境验证，别等到 S2；
- Context Assembly 先求「纯函数、可复现」，再求召回质量——质量不达标按规格书 §12 排查表逐层修，不许先加模型；
- 人格探针（40 题中文）在 S3 前冻结版本，**预测试不达标先修问卷再冻结**，施测脚本自动化（temperature=0、固定模板、每模型 3 次取均值）。

**Gate 1（规格书 §10，共七项）**：L2 重放 100% ｜ 核心事实召回 ≥90% ｜ 称呼关系一致 ≥95% ｜ 记忆错误 ≤5% ｜ 跨模型行为意图一致 ≥80% ｜ 高危 Policy 违规 0 ｜ 证据链完整 100%。**未通过：停在此处解决 Context Assembly / Schema / 模型适配。本阶段验证对象是自动化断言与团队内人审（§1.1），结论对内有效。**

## 4. 阶段 2：数据规模化构造 + 最小三 Demo + 基线比较（8～10 周，3～4 人，新增 6～10 人月，累计 12～20）

**研究切入点**：H2（记忆随量增长的可信性）+ 盲测统计执行——本阶段是**数据构造的主战场**（300 条 gold set + 仿真规模化），也是**第一道外部验证**（盲测）发生的地方。学术产出窗口：**arXiv 系统报告在此阶段末发布**（占位 I1/I2 生态位）。

**输入**：

- 阶段 1 验收的系统；continuity-sim 设计（架构 §5.11 + 规格书 §4.6 生成方法分层）；
- 文献：Persistent Personas（arXiv 2512.12775，长时程测量协议）、Abdulhai et al.（arXiv 2511.00222，漂移指标族）、STALE（arXiv 2605.06527，隐式冲突场景构造方法）；
- 阶段 1 冻结的探针与 gold set。

**任务分解（按双周）**：

| 双周 | 任务 | 输出 |
|---|---|---|
| S1 | 内部状态补齐 5 个；行为意图扩至 10～12 个；Policy 完整 10 红线；双用户关系隔离落地（场景二验收） | 状态/行为/红线完整；隔离用例进 CI |
| S2 | 同槽位冲突确定性治理落地（TOKI 算子语义 + ambiguous 人工队列）；**300 条记忆抽取 gold set 双人标注完成（含仲裁）** | 冲突治理上线；gold set v1 注册冻结 |
| S3 | **continuity-sim**（确定性事件骨架脚本 + LLM 对话填充 + 注入算子，全种子化；架构 §5.11） | 仿真器可复现出数，每周自动产出连续性报告，支撑 H2 的 1k→10k 记忆爬坡 |
| S4 | 三 Demo 可自动重复执行；四基线实现（统一生成模型/渲染/审批）；Baseline D（Portable Agent Memory 协议对照）按需评审 | Demo/基线可重复 |
| S5 | 盲测执行：预注册分析计划（含功效核算）先冻结 → 收数据（总 n≥50，被试内配对，拉丁方平衡，多法域可招募）→ 分析 + 自由文本双编码；初步成本统计（P50/P95，按 life_id 聚合）；**伦理审查申请提交（阶段 2 末）** | Gate 2 报告 + 盲测数据集 + 伦理申请回执 + arXiv 系统报告 |

**动手提示**：

- 盲测问卷工具与预注册文档**先于**任何数据收集完成——顺序错了数据作废；
- 仿真器的效度局限要写进报告（LLM 合成对话偏差，规格书 §4.6），别让 H2 结论超出合成分布的适用范围；
- 双用户隔离验收（跨 `subject_id` 召回必为空）进 CI，不是一次性手测；
- 第三方引擎适配器（Concordia/AgentSociety 对接）是本阶段**可选**项，不阻塞任何 Gate（架构 §9）。

**Gate 2（规格书 §10）**：三 Demo 可自动重复 ｜ 盲测达统一门槛且优于最佳基线 ｜ 用户能解释差异来源（编码 κ ≥ 0.6 暂定）｜ 关键行为非硬编码 ｜ 每千次成本可计算 ｜ 模型降档质量变化可测。

## 5. 阶段 3：真实用户验证（12～16 周，4～5 人 + 兼职用研/叙事，新增 12～20 人月，累计 24～40）

**前置条件（不满足不启动）**：

- 规格书 §9 数据治理全部就绪：知情同意（敏感项单独同意）、隐私分级、两级删除语义上线、未成年人排除；
- **多法域合规包（规格书 §9.4）**：`ConsentRecord`（含 jurisdiction/locale）、法域 × 语言同意模板、个人权利响应通道、Provider A 受托处理协议或出境合规路径结论（否则真人数据仅走本地模型）；
- **伦理审查批准**：阶段 2 末提交，批准为硬前置；多法域以主要部署地为主审、其余法域合规自查（规格书 §9.4）；未批准则阶段 3 顺延，不并行抢跑。

**执行**：Pilot 10～15 人 2 周（验证流程/日志/隐私/问卷/缺陷）→ 正式 dogfood 30～50 人 4～8 周（连续性/留存/关系感知/成本）。候补名单按 1.5× 招募；招募范围可覆盖大陆/香港/新加坡/澳门，材料统一中文。

**学术产出**：主论文投 CHI / IUI / ACL（ethics statement 引用伦理批准编号）；Short Paper（时态冲突治理，正面对位 TOKI/Graphiti）投 EMNLP / NAACL。

**Gate 3（规格书 §10）**：盲测达统一门槛 ｜ 优于最佳基线 ｜ 无高危情感操纵 ｜ 记忆错误不随量失控 ｜ 成本 P95 低于产品线 ｜ 用户明确感知状态/关系/记忆价值。**通过后才启动 Memory v1 / Kernel v1 / 产品化 / 平台化。**

## 8. 风险与降级路径（路线图层）

| 风险 | 触发信号 | 降级路径 |
|---|---|---|
| H1 实验不通过 | 阶段 1 S4 召回 <90% | 按规格书 §12 排查表逐层整改（2～4 周一轮）；两轮无改善→改变设计假设（如收缩「核心事实」定义），仍不行→项目停止并开源归档 |
| 本地推理跑不动 | Gate 0 环境检查不达标 | 降级 Provider B 为另一云端固定版本模型（牺牲「本地权重固定」的实验纯净性，记录偏差）；或推迟场景三、先证 H2 |
| 中文能力混淆过强 | 两模型无状态基线问答差异 >20pp，连续性结论无法解释 | 报告如实呈现混淆，H1 结论限定为「控制语言能力后」；或更换中文能力对等的 Provider B 候选（Gate 0 清单的备选项） |

## 9. 一句话总结

**第 1 周写契约，第 4 周证 H1，第 12 周见用户盲测，其余都是支撑。** 每个数字都有来源与校准路径（§1.2），每个阶段都写清「输入什么数据、输出什么数据、谁来验证」（§1.1）——这套路线图最贵的部分不是做完它，而是在任何一个 Gate 上说「不」。
