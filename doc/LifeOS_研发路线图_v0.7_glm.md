# LifeOS 研发路线图 v0.7（GLM 版）

**从哪里开始 · 研究切入点 · 阶段性输入输出 · 动手难易序**

版本 v0.7 ｜ 2026-08-06 ｜ 配套：[`LifeOS_产品规格说明书_v0.7_glm.md`](doc/LifeOS_产品规格说明书_v0.7_glm.md)、[`LifeOS_系统架构设计_v0.7_glm.md`](doc/LifeOS_系统架构设计_v0.7_glm.md) ｜ 评审依据：[`adadmic_innovation-glm.md`](doc/adadmic_innovation-glm.md)

> 本文件回答「怎么上手、从哪开始、每阶段输入输出是什么、先做什么最省力」。核心原则：**先杀最高风险假设，再建完整运行时**。v0.6 的阶段 0 先建 schema（低风险），但最高风险假设 H1（模型无关连续性）要到 Gate 1 才测——若失败，前期投入虽不白费但已晚。故 v0.7 在四阶段前插入 **Spike 0** 低成本 kill-switch。
>
> 秉承实事求是：所有人月为工程中位估算（误差 ±30%），用于规划不构成承诺；所有指标为工程起点，阶段 1 校准后冻结。

---

## 0. 总体路径与决策门

```
Spike 0 (H1 kill-switch, 1–2 周)
  └─ Spike 0 Gate: 召回远低于90%且不可修复 → 停；否则进 Phase 0
Phase 0 契约与可重放骨架 (3 周) ── Gate 0
Phase 1 跨模型连续性最小验证 (6–8 周) ── Gate 1
Phase 2 三 Demo + 基线 + continuity-sim (8–10 周) ── Gate 2
Phase 3 真人验证 (12–16 周) ── Gate 3
  └─ 通过后启动扩张（Memory v1 / Kernel v1 / 产品化）
```

每阶段可独立停止，逐级授权，不一次性批准。

## 1. 研究切入点优先级（学术价值 × 工程可行）

| 优先级 | 切入点 | 学术价值 | 工程可行 | 说明 |
|---|---|---|---|---|
| P1 | I1+I2 跨模型连续性 + 量化协议 | 最高 | 中（Spike 0 即出初步证据） | 论文核心，最早可产生证据 |
| P2 | I4 时态冲突治理 | 高 | 高（范围小、对位 TOKI 清晰） | **建议第一篇 Short Paper**，快速积累引用 |
| P3 | I3 三级事件回放 | 中（系统资产） | 高（随 Phase 0/1 自然产出） | arXiv 报告低成本 |
| P4 | I6 依恋安全 policy-as-code | 中（社会价值高） | 中（随 Phase 2 Policy 完整化） | 差异化在执行层 |
| P5 | I5 Schema/协议 | 中（白地但锚点少） | 低（需实例增长才体现价值） | 长线 |

**建议第一篇产出**：I4 Short Paper（EMNLP/NAACL 资源方向）。理由：范围小、对位 Graphiti/Zep 与 TOKI 清晰、可在 Phase 1 末/Phase 2 初成稿，先于主论文积累引用与可信度。

## 2. 阶段化输入输出（按动手难易序）

### 2.1 Spike 0：H1 最廉价证伪（前置，最先做）

- **目的**：建运行时前，用最小成本测核心论点「外部化状态组装能否让换模型后事实/风格连续」。
- **周期/团队/投入**：1～2 周 ｜ 1 人 ｜ 0.25～0.5 人月
- **输入**：
  - 2 个模型（1 云 + 1 本地开源，锁定版本）；
  - 50 条核心事实集（人工编写，覆盖事实/偏好/关系）；
  - 1 份人格契约文本（人格种子草案）；
  - 最小 Context Assembly 脚本（状态 + Top-K 记忆 + 关系得分 + 人格契约 → system role）；
  - 改编大五简版 40 题探针（用于初测漂移）。
- **输出**：
  - 换模型后核心事实召回率（初值）；若事实召回 < 80% 且无法通过 Prompt 优化改善，H1 危险，暂停
  - 人格探针漂移度（初值，仅供趋势，不作门）；
  - 一份「H1 是否值得继续投入」的判断报告。
- **Spike 0 Gate（kill-switch）**：
  - 召回远低于 80% 且 Context Assembly 无法修复 → **H1 危险，暂停建运行时**，回到假设/方法重审；
  - 召回接近/达标 → 进入 Phase 0。
- **难易**：**最低**。纯脚本，无 Policy/事件模型/DB schema。**强烈建议作为第一件事**。
- **诚实声明**：Spike 0 不证明 H1 成立，只排除「最廉价就能证伪」的情况，降低后续投入风险。

### 2.2 Phase 0：契约与可重放骨架
- **目标**：将 Spike 0 的概念沉淀为代码——实现 12 个核心实体的 Schema、L0/L1/L2 事件管线、确定性重放，以及最小化的 Policy 审批骨架
- **周期/团队/投入**：3 周 ｜ 2 人 ｜ 1～2 人月 ｜ 累计（含 Spike 0）1.25～2.5 人月
- **输入**：12 实体清单、规格 §6、架构设计全文、Spike 0 的人格契约/事实集。
- **交付**：
  - 12 核心实体 Schema + L0/L1/L2 事件协议 + Alembic 迁移；
  - 50 条核心事实集 + 30 个行为场景；
  - **威胁模型草案**（架构设计 §9.1 STRIDE）；
  - 回放骨架（faithful 模式）。
- **技术栈**：Python / FastAPI / Pydantic / SQLAlchemy / Alembic / PostgreSQL / pytest / Docker Compose。
- **不引入**：Temporal / Valkey / LangGraph / Mem0 / Next.js / 行为树 / 本地大模型部署。
- **Gate 0**：示例事件全链路 round-trip；相同 L2 重放（faithful）100% 一致；LLM 输出不能直写权威表；Policy 拒绝后无状态副作用；最低硬件配置清单环境检查通过。
- **未通过**：只改 Schema/事件协议/事务边界，不继续 UI 与 Demo。
- **难易**：低–中。主要是设计与契约，代码量不大，但决定后续一切。
- **特别注意**：此时开始建立 人格种子生成函数 的冻结版本（纯确定性，如基于哈希的人格参数初始化），确保后续实验可复现。

### 2.3 Phase 1：跨模型连续性最小验证
- **目标**：在真实数据库和推理引擎中，证明 LifeOS 的确定性主干确实能让换模型后硬指标达标。
- **周期/团队/投入**：6～8 周 ｜ 2～3 人 ｜ 新增 5～8 人月 ｜ 累计 6.25～10.5 人月
- **输入**：Phase 0 产物、核心事实集(core fact gold set)扩至 ≥300、本地推理部署（vLLM/llama.cpp）。
- **范围**：1 Life Instance / 1 用户 / 纯文本 / 3 内部状态 / 3 维关系 / 2 类持久记忆 / 6 行为意图 / 2 模型 Provider / 30 行为场景。
- **前置**：人格探针信度校准（ICC≥0.7）→ 再冻结漂移阈值。
- **交付**：跨模型连续性最小验证 + Gate 1 六项硬指标 + 判别效度初测。
- **技术栈**：FastAPI 模块化单体 / PostgreSQL / pgvector 精确检索 / Gradio 调试台（含认证）/ 自研 Model Adapter / vLLM 或 llama.cpp / pytest + 评估脚本。
- **关键动作**：
    实现惰性衰减、乐观并发；
    实现精确检索 + 未索引兜底；
    集成 2 Provider 热切换；
    搭建 Eval Harness CI，对接 gold set；
    对人格探针进行信度校准（ICC）和初步效度检验（专家评分关联）。
- **Gate 1**：L2 重放 100% ｜ 核心事实召回 CI 下限 ≥90% ｜ 称呼关系一致 ≥95% ｜ 记忆错误 ≤5% ｜ 跨模型行为意图一致 ≥80% ｜ 高危 Policy 违规 0 ｜ 证据链完整 100%。
- **未通过**：停在此处解决 Context Assembly / Schema / 模型适配，不靠加模型或基础设施掩盖。
- **难易**：中。引入本地推理部署是主要工程量（约 1～2 人月，已计入）。

### 2.4 Phase 2：三 Demo + 基线 + continuity-sim
- **目标**：产出可反复运行的三个场景 Demo，证明 LifeOS 在盲测中优于 RAG/摘要/纯历史基线。
- **周期/团队/投入**：8～10 周 ｜ 3～4 人 ｜ 新增 6～10 人月 ｜ 累计 12.25～20.5 人月
- **输入**：Phase 1 产物、四基线实现、盲测问卷工具、预注册分析计划。基本仿真器设计蓝图。
- **增加**：内部状态补齐至 5 / 10～12 行为 / Policy 完整 10 红线 + Output Guard / Embedding Outbox Worker / 同槽位事实版本 / 2 独立用户关系 / 事件行为回放界面 / continuity-sim 时间加速仿真器 / 三 Demo / 初步成本统计（含本地推理摊销）。
- **关键**：**先实现 Baseline C（标准 Vector RAG）**——它是最强竞争者，越早知道 LifeOS 是否能赢越好。
- **关键动作**：
    开发 continuity-sim 产生 7 天分离-重逢场景；同时用真人 Pilot 的少量数据校准仿真器错误模式。
    构建 Baseline A/B/C 作为对照，先实现 Baseline C（最强对比）。
    搭建 Gradio 调试台（仅用于实验操控，不含终端用户交互设计）。
    招募 ≥ 50 名评定者进行组内盲测，严格执行预注册分析和多重比较校正。
    实施双闸安全（意图层 + 输出层），将 L1 指令检测加入 Policy。
- **必须**：四基线对照（A/B/C/LifeOS）+ 盲测统计规范（组内设计、n≥50、bootstrap CI、多重比较校正、预注册、判别效度）。
- **Gate 2**：三 Demo 可自动重复 ｜ LifeOS 盲测达统一门槛且（校正后）优于最佳基线 ｜ 用户能解释差异来源 ｜ 关键行为非硬编码脚本 ｜ 每千次成本可计算 ｜ 模型降档质量变化可测。
- **难易**：中–高。continuity-sim 与盲测组织是主要复杂度。

### 2.5 Phase 3：真实用户验证
- **目标**：在受控 dogfood 中证明连续性价值，并完成学术发表的全部数据收集。
- **周期/团队/投入**：12～16 周 ｜ 4～5 人 + 兼职用研/叙事 ｜ 新增 12～20 人月 ｜ 累计 24.25～40.5 人月
- **前置条件**：数据治理与合规全部就绪（IRB/伦理审查、DPIA、DPA、隐私分级、删除验证、加密、认证、审计、未成年人排除）。
- **分两批**：Pilot 10～15 人 2 周（流程/日志/隐私/问卷/缺陷）→ 正式 dogfood 30～50 人 4～8 周（连续性/留存/关系感知/成本）。
- **关键动作**：
    Pilot 2 周，调试隐私流程、日志采集、用户反馈通道；
    正式 30～50 人 4～8 周，采集连续性指标、用户感知问卷、自愿使用频率；
    进行 L1 对抗攻击的红队测试，验证防御；
    撰写论文草稿，报告真人数据结论。
- **Gate 3**：盲测同一身份识别达统一门槛 ｜ 优于最佳基线 ｜ 无高危情感操纵 ｜ 记忆错误不随量失控 ｜ 成本 P95 低于产品线 ｜ 用户明确感知状态/关系/记忆价值 ｜ 最小用户价值软门（Pilot「愿意继续使用」+ 日均互动次数）。
    用户“愿意继续使用”比例 > 70%，日均互动次数维持稳定，则证明软资产连续性具有用户价值。
- **难易**：高。合规与用研组织是主要风险（见风险登记）。


### 2.6 路线图中交互与硬件的隔离声明 
- 所有阶段不开发终端用户交互 APP/Web，只保留最小化调试台供实验人员使用。真实的对话界面、语音表情等，由另一产品或团队在决策门后基于 LifeOS API 实现。
- 不实现任何硬件驱动、传感器数据处理；Life Kernel 的状态仅来自于 L0 文本事件（或将来由硬件适配层翻译后的文本事件），保证平台纯粹性

## 5. 「动手难易」指导原则

1. **先验假设，后建系统**：Spike 0 用最小代码验最贵假设。若 Spike 0 即暴露 H1 风险，省下后续 20+ 人月的大部分。
2. **先契约，后实现**：Phase 0 冻结 Schema/事件协议/事实集/场景，再写模块代码，风险显著降低。
3. **先基线，后宣称**：Phase 2 先实现最强基线 C，再宣称 LifeOS 优势——没有基线的 75% 不构成证据。
4. **先确定性，后概率性**：确定性主干先跑通（可重放、可审计），LLM 作为叶子后接入，避免概率性污染权威状态。
5. **先本地，后云**：本地推理（敏感路径 + Provider B）先部署，纵向实验用固定权重，避免云端静默升级破坏实验条件。
6. **先安全设计，后真人**：威胁模型/加密/认证/审计在 Phase 0–1 设计，Phase 3 前就绪，合规不是补充条款。

## 6. 风险与 kill-switch

| 阶段 | 主要风险 | kill-switch |
|---|---|---|
| Spike 0 | H1 在最廉价测试即暴露 | 召回远低 90% 且不可修复 → 停，重审假设 |
| Phase 0 | 契约设计错误返工 | Gate 0 不过 → 只改 Schema/事件协议/事务边界 |
| Phase 1 | Context Assembly/模型适配失败 | Gate 1 不过 → 停在此解决，不加模型掩盖 |
| Phase 2 | 盲测不优于基线 / 统计功效不足 | Gate 2 不过 → 优化行为与关系表达，不加数据库；连续两轮无改善改设计假设 |
| Phase 3 | 合规/招募不足 | 前置 IRB/DPIA；Pilot 先行；候补 1.5× |

每轮整改控制在 2～4 周，只解决一个明确假设，重跑同一冻结测试集。连续两轮无改善，应改变设计假设而非无限投入。

## 8. 诚实声明

- 所有人月为工程中位估算（误差 ±30%），用于规划不构成承诺；
- Spike 0 不证明 H1 成立，只排除最廉价证伪情形；

- 失败结论也写入 ADR 公开（No-Go 时全部资产按 Apache-2.0 开源归档）。
