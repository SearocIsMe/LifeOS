# LifeOS 研发路线图 v0.8

**配套文档**：《LifeOS 产品规格说明书 v0.8》（Gate 阈值与授权上限以规格书 §10 为准）；《LifeOS 架构设计 v0.8》（字段与接口以架构文档为准）。

版本 v0.8 ｜ 2026-08-06 ｜ 首次独立成文

> 本文档回答「怎么动手」：研究切入点选哪里、每个阶段的输入/输出/动手难易度、第一周具体做什么。核心原则：**先做最容易验证的事，先证最危险的假设**。

---

## 0. 资源与边界假设（显式声明，非承诺）

以下假设来自规格书与决策层确认，任一变化须重排本路线图：

- **团队**：阶段 0～1 按 2～3 人计（1 架构负责人 0.5 FTE + 1～2 Python/AI 工程师 + 1 后端/DB 工程师）；
- **算力**：本地推理（Provider B）按单 GPU 工作站最低配置规划， Gate 0 环境检查时确认；云端大模型按 API 计费；
- **范围**：不做运动控制、不做产品交互界面（规格书 §1.1）；
- **工期口径**：人月为工程中位估算，误差 ±30%。

---

## 1. 总体策略：先证最危险的假设

三条假设的危险度排序：**H1（身份连续可工程化）> H2（记忆可信）> H3（用户可感知）**。H1 是全部价值的地基——如果换模型就「换人」且修不好，后面都不必做。因此：

- **研究切入点 = H1 的最小实验**（场景三「换模型它还是它」的雏形），而不是先把平台做全；
- **工程切入点 = 契约先行**（Schema + 事件协议 + 回放），这是后续一切的地基，也是最容易动手的部分（纯数据建模，无 ML 不确定性）;
- 每个阶段都能独立停止， Gate 未过不进入下一阶段。

动手难易度总览（★越多越难，难点在不确定性而非工作量）：

| 阶段 | 难易度 | 主要不确定性 |
|---|---|---|
| 0 契约与骨架 | ★ | 几乎无，纯工程 |
| 1 跨模型连续性 | ★★★ | Context Assembly 能否撑起 ≥90% 召回（H1 核心风险） |
| 2 三 Demo + 基线 | ★★ | 盲测组织与统计执行（流程风险大于技术风险） |
| 3 真实用户验证 | ★★★★ | 招募、合规、长周期运维 |

---

## 2. 阶段 0：契约与可重放骨架（3 周，2 人，1～2 人月）

**为什么从这里开始**：它是唯一「做对做错立刻知道」的阶段——回放一致率要么 100% 要么不是，没有模糊地带；且全部后续工作都建立在这份契约上。

**输入**：

- 规格书 §3/§5/§6（功能与模块概述）；
- 架构设计 §3（事件模型）、§4（12 实体字段表）；
- 文献：ActiveGraph（arXiv 2605.21997）与 ESAA（arXiv 2602.23193）——参考其 append-only 日志与意图/提交分离的具体实现，避免踩坑。

**任务分解（按周）**：

| 周 | 任务 | 输出 |
|---|---|---|
| W1 | 仓库与 CI 骨架；PostgreSQL+pgvector Docker Compose；12 实体 Pydantic Schema + Alembic 迁移 | 可启动的空系统；Schema v0.1 |
| W2 | L0/L1/L2 事件协议 + `deterministic_commit` 函数（在线/回放同一路径）；Policy Engine 最小骨架（2 条红线先跑通审批流） | 事件管线 round-trip |
| W3 | 50 条核心事实集 + 30 个行为场景落库；回放取证脚本；Gate 0 验收 | Gate 0 报告 |

**动手提示**：

- W1 没有任何研究成分，目标是第二天就能 `docker compose up`；
- `deterministic_commit` 是全局最关键的函数，先写它的纯函数签名再写任何存储代码；
- 50 条核心事实集是**人工编写**的，别试图用 LLM 生成——它是后续所有测量的标尺。

**Gate 0（规格书 §10）**：示例事件全链路 round-trip；相同 L2 重放 100% 一致；LLM 输出不能直写权威表；Policy 拒绝后无状态副作用。**未通过：只改 Schema/事件协议/事务边界，不继续做 UI 与 Demo。**

---

## 3. 阶段 1：跨模型连续性最小验证（6～8 周，2～3 人，新增 5～8 人月，累计 6～10）

**研究切入点（本阶段唯一的研究目标）**：H1 最小实验——

> 同一 Life Instance，相同结构化状态，Provider A（云端）→ Provider B（本地），核心事实召回能否 ≥90%？

这是全项目**单位投入信息量最大**的实验：通过则 H1 有工程证据，主论文论点成立一半；不通过则第 4 周就知道，整改成本最低。

**输入**：

- 阶段 0 的契约与骨架；
- 文献：Portable Agent Memory（arXiv 2605.11032，状态迁移协议参考）、SPASM（arXiv 2604.09212，外部表示重注入参考）、PICon（arXiv 2603.25620，一致性测量方法）；
- 本地推理最低配置确认（Gate 0 环境检查项的闭环）。

**任务分解（按双周）**：

| 双周 | 任务 | 输出 |
|---|---|---|
| S1 | Life Kernel（3 状态惰性衰减）+ Relationship Engine（有界规则）；Memory OS 写入管线（含 Embedding Outbox） | 状态可更新、记忆可写入 |
| S2 | Context Assembly 纯函数 + Model Gateway 双 Provider + 本地推理部署（vLLM/llama.cpp，1～2 人月大头在此） | 双模型可切换 |
| S3 | Behavior Planner（6 意图 Utility Scoring）+ Gradio 调试台最小版；核心事实集扩至 100 条 | 端到端可对话 |
| S4 | **H1 最小实验**：场景三雏形跑通，八项指标中的 6 项出数；Gate 1 验收 | Gate 1 报告 + H1 实验记录 |

**动手提示**：

- 本地推理部署是全阶段最大工作量项，**第一周就并行启动**环境验证，别等到 S2；
- Context Assembly 先求「纯函数、可复现」，再求召回质量——质量不达标按规格书 §12 排查表逐层修，不许先加模型；
- 人格漂移度探针（40 题）在 S3 前冻结版本，施测脚本自动化。

**Gate 1（规格书 §10）**：L2 重放 100% ｜ 核心事实召回 ≥90% ｜ 称呼关系一致 ≥95% ｜ 记忆错误 ≤5% ｜ 跨模型行为意图一致 ≥80% ｜ 高危 Policy 违规 0 ｜ 证据链完整 100%。**未通过：停在此处解决 Context Assembly / Schema / 模型适配。**

## 4. 阶段 2：最小三 Demo + 基线比较（8～10 周，3～4 人，新增 6～10 人月，累计 12～20）

**研究切入点**：H2（记忆随量增长的可信性）+ 盲测统计执行。学术产出窗口：**arXiv 系统报告在此阶段末发布**（占位 I1/I2 生态位，对冲规格书 §13 文献边界侵蚀风险）。

**输入**：阶段 1 验收的系统；continuity-sim 设计（架构文档 §5 事件模型复用）；文献：Persistent Personas（arXiv 2512.12775，长时程测量协议）、Abdulhai et al.（arXiv 2511.00222，漂移指标族）、STALE（arXiv 2605.06527，隐式冲突场景构造方法）。

**任务与输出**：

- 内部状态补齐 5 个、行为意图 10～12 个、Policy 完整 10 红线；
- 同槽位冲突确定性治理落地（参考 TOKI 算子语义 + ambiguous 人工队列，架构 §5.2）；
- **continuity-sim 时间加速仿真器**（1 真实日 ≈ 30 模拟日）：覆盖分离/重逢/纠正/冲突/偏好变化，每周自动产出连续性报告，支撑 H2 的 1k→10k 记忆爬坡；
- 三 Demo 可自动重复执行；四基线（A/B/C/LifeOS）实现；Baseline D（Portable Agent Memory 协议对照）按需评审；
- 盲测执行：n≥50、bootstrap CI、预注册分析计划先冻结后收数据；至少 1 名非开发成员参与；
- 初步成本统计（P50/P95 分布）。

**动手提示**：仿真器与三 Demo 是两条可并行的线；盲测问卷工具与预注册文档**先于**任何数据收集完成——顺序错了数据作废。

**Gate 2（规格书 §10）**：三 Demo 可自动重复 ｜ 盲测达统一门槛且优于最佳基线 ｜ 用户能解释差异来源 ｜ 关键行为非硬编码 ｜ 每千次成本可计算 ｜ 模型降档质量变化可测。

---

## 5. 阶段 3：真实用户验证（12～16 周，4～5 人 + 兼职用研/叙事，新增 12～20 人月，累计 24～40）

**前置条件**（不满足不启动）：规格书 §9 数据治理全部就绪——知情同意、隐私分级、删除可验证、未成年人排除。

**执行**：Pilot 10～15 人 2 周（验证流程/日志/隐私/问卷/缺陷）→ 正式 dogfood 30～50 人 4～8 周（连续性/留存/关系感知/成本）。候补名单按 1.5× 招募。

**学术产出**：主论文投 CHI / IUI / ACL；Short Paper（时态冲突治理，正面对位 TOKI/Graphiti）投 EMNLP / NAACL。

**Gate 3（规格书 §10）**：盲测达统一门槛 ｜ 优于最佳基线 ｜ 无高危情感操纵 ｜ 记忆错误不随量失控 ｜ 成本 P95 低于产品线 ｜ 用户明确感知状态/关系/记忆价值。**通过后才启动 Memory v1 / Kernel v1 / 产品化 / 平台化。**

## 6. 研究切入点地图（I1–I6 各自从哪里上手）

| 创新点 | 上手动作 | 依附阶段 | 难易度 |
|---|---|---|---|
| I1 跨模型连续性 | 阶段 1 S4 的 H1 最小实验——先有 90% 召回证据，再谈方法创新 | 1 | ★★★ |
| I2 连续性评测 | 把 PICon 三轴 + Abdulhai 漂移指标改造为跨模型版本，先在 gold set 上复现单模型结果再扩展 | 1～2 | ★★ |
| I3 解释存档回放 | 阶段 0 的 `deterministic_commit` + provenance 字段——架构即贡献，无需额外研究 | 0 | ★ |
| I4 时态冲突治理 | 先复现 STALE 基准场景（400 隐式冲突），验证规则裁决 vs LLM 裁判的差距 | 2 | ★★ |
| I5 Life Schema | 阶段 0 的 12 实体 + 导出格式即初稿；阶段 2 后整理为协议草案发布 | 0→2 | ★ |
| I6 红线即代码 | 把 10 红线逐条翻译成可执行规则 + 对应测试用例（对照 Harmful Traits 特质清单查漏） | 1～2 | ★★ |

**原则**：每个切入点都先复现/对位已有文献，再声明增量——与规格书 §15「新颖性声明先查证」一致。

## 7. 第一周动手清单（Day 1–5，具体到天）

- **Day 1**：仓库初始化（`pyproject.toml`、pre-commit、CI 骨架）；`docker-compose.yml`（postgres+pgvector）；ADR-0001（记录 v0.8 范围边界与文档三分）。
- **Day 2**：`LifeInstance / RawEvent / InterpretedEvent / DomainEvent` 四个实体的 Pydantic 模型 + Alembic 首迁移。
- **Day 3**：`deterministic_commit(event, schema_version, policy_version) -> DomainEvent` 纯函数签名 + 单测骨架（先测后写）。
- **Day 4**：剩余 8 实体 Schema；核心事实集编写开工（每人 10 条，互审）。
- **Day 5**：事件管线最小 round-trip 脚本跑通（L0→L1 mock→L2→状态写）；周会核对 Gate 0 清单差距。

**环境检查项（Gate 0 前置）**：GPU 工作站可用性（型号/显存记录入 ADR）；云端 Provider API key 与计费告警；Docker/Podman 版本。

## 8. 风险与降级路径（路线图层）

| 风险 | 触发信号 | 降级路径 |
|---|---|---|
| H1 实验不通过 | 阶段 1 S4 召回 <90% | 按规格书 §12 排查表逐层整改（2～4 周一轮）；两轮无改善→改变设计假设（如收缩「核心事实」定义），仍不行→项目停止并开源归档 |
| 本地推理跑不动 | Gate 0 环境检查不达标 | 降级 Provider B 为另一云端固定版本模型（牺牲「本地权重固定」的实验纯净性，记录偏差）；或推迟场景三、先证 H2 |
| 盲测招募不足 | 阶段 2 第 4 周 n<30 | Pilot 转正式的标准不降；候补 1.5×；仍不足→缩小场景只跑场景三盲测 |
| 文献被抢发 | 季度检索发现 I1/I2 空白被占 | 转向工程护城河（I3–I6）+ 基准开源占位；学术目标降级为系统论文 |
| 人月超支 30% | 任一阶段实际投入超上限 | 触发规格书 §10 授权复审：砍范围（先砍 Demo 数量，再砍状态维度），不加人 |

---

## 9. 一句话总结

**第 1 周写契约，第 4 周证 H1，第 12 周见用户盲测，其余都是支撑。** 每个阶段都有明确的停止条件——这套路线图最贵的部分不是做完它，而是在任何一个 Gate 上说「不」。
