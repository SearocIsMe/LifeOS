## 1. 产品定位与核心承诺

### 1.1 定位（v0.9.2 修订：硬件彻底解耦）

**Idensona 是一套以软件形式交付的「身份与人格连续性内核」**：它持有并治理 AI 陪伴体的七类一等资产——身份、生命状态、记忆、人格、关系、发展史、行为政策——使同一个"它"跨越模型、设备与时间仍然是它。

**四句话定位**：

1. **它是内核，不是产品**：不卖硬件、不卖整机、不自建语音管线；以 **SDK / 服务 / 引擎** 三种形态存在。
2. **它是生态的锚**：前端（ESP32 系列）、语音管线（xiaozhi-server）、模型服务（云或边缘）、载体（机器人/桌面/形象）**都可替换**，唯有 Idensona 提供的能力不可替换——因为它是连续性的持有者。
3. **它的价值可被验证**：`Idensona + elderly-companion` 是"用既有整机链路验证内核"的**验证场**，不是要做的产品本身。
4. **它不做硬件**（用户确认）：顶多做几个选定硬件上的 demo，用于展示内核能力。

**基础管理对象（不变）**：

```
Idensona Instance = Identity + Life State + Memory + Personality
                  + Relationships + Development History + Behavior Policy
```

**核心产品承诺（不变）**：大模型可以更换，数据库可以迁移，硬件身体可以升级，但生命实例仍应被用户识别为「同一个它」。

### 1.2 范围边界（v0.9.2 重写：从"做什么/不做什么"升级为"谁做"）

> v0.9.1 的边界是**二分法**（我们做 / 我们不做）。v0.9.2 的边界必须是**三分法**（我们做 / 生态做 / 明确不做），因为生态里已经有人把语音、设备管理做完了。

| # | Idensona **做** | 生态**做**（不重做） | **明确不做**（永不） |
|---|---|---|---|
| B1 | 身份管理、人格契约、主体关系 | 语音采集、唤醒、AEC、编解码 → **前端固件（xiaozhi）** | 硬件设计 / BOM / 结构 |
| B2 | 状态演化（惰性衰减）、情绪状态写入 | ASR / TTS / LLM 推理 → **xiaozhi-server + 模型服务** | 自研 ASR/TTS/LLM 引擎 |
| B3 | 记忆写入/召回/双时态治理/两级删除 | 设备管理、绑定、OTA、运营台 → **xiaozhi-server + 智控台** | 微服务拆分（仍不做；多租户与编排现已列入范围，见 §7.5） |
| B4 | 人格与关系动力学（版本化、可回放） | 运动控制、底盘、SLAM → **载体/机器人栈** | 运动控制与运动学参数（RED-10 冻结） |
| B5 | 行为意图规划 + 10 红线审批 + 逐笔留痕 | 硬件量产、结构、电源 → **硬件合作方** | 论文实验与投稿（用户已排除） |
| B6 | 情绪**解释**与状态映射（Emotion 模块） | 情绪**表达**（表情/音色/语速）→ **前端与本机 TTS** | 表情动画渲染实现 |
| B7 | 评估量尺、回放取证、审计导出 | 观测栈与评估框架 → **现成（Langfuse/DeepEval 等）** | 自研评估框架与观测栈 |
| B8 | 治理：Consent / 隐私分级映射 / 出境窄门判定 | 法规解释与法律意见 → **法务** | 法律意见输出 |

**边界的物理断言**（CI 可验，架构 §1.3 已定义）：

- `src/lifeos/` 内**不得出现** I2S / DVP / GPIO / UART / 舵机 / ROS2 依赖（B1/B4 反证）；
- `src/lifeos/` 内**不得出现** ASR/TTS 模型推理代码（B2 反证）；
- 结构化行为意图**不得携带任何运动学参数**（`KINEMATIC_KEYS` 已固化，RED-10 已实现）。

### 1.3 「同一个它」判定框架（**完全沿用 v0.9.1 §1.3**）

三层判定主体与通过标准不变：

| 层 | 判定主体 | 通过标准 |
|---|---|---|
| **S1 系统断言层** | CI 自动化 | Identity/人格契约/关系状态零变化；L2 重放一致率 100% |
| **S2 行为层** | Eval Harness 探针 | 核心事实召回 ≥90%；称呼关系一致 ≥95%；人格漂移 RMSD ≤0.15；跨模型意图一致 ≥80% |
| **S3 用户感知层** | 人类盲测（被试内配对，n≥50） | 「是不是同一个它」一致率 ≥75% 且 ≥ 最佳基线 +10pp |

**v0.9.2 唯一补充**：S1 层新增**第三组断言**——**接缝层断言**（见 §3.5.4）：接缝无状态性、身份映射唯一性、跨 life_id 必为空。这是接缝层引入后必须新增的硬门。

### 1.4 核心工程立场（**沿用 v0.9.1 §1.4**）

确定性主干 + 概率性叶子；LLM 只在叶子（候选意图/抽取/渲染），不写权威状态；四道锁（L1 存档或候选池、Policy 先于事务、切换前后断言、逐笔 provenance）**全部不变**。

**v0.9.2 补充一行职能**：

| 职能 | 性质 | 执行者 | 归入该侧的理由 |
|---|---|---|---|
| **情绪解释（声学+文本融合）** | **确定性规则为主、LLM 抽取为辅** | Emotion 模块 | 融合器必须是确定性加权，否则同一输入两次结果不同，破坏"可取证"（E1/E2 验收） |

## 2. 三条可证伪假设（**沿用 v0.9.1 §2，措辞按 v0.9.2 校订一处**）

| 假设 | 内容 | 证伪条件 |
|---|---|---|
| **H1 身份连续可工程化** | 身份连续性主要由外部化状态（Schema + 记忆 + 关系 + 人格参数）决定，而非由具体模型权重决定。 | 双模型热切换下核心事实召回率 < 90% 且无法通过上下文组装修复。 |
| **H2 长期记忆可信且可测量** | 记忆错误率与冲突率可被测量，并被治理手段压到阈值以内。 | 随记忆量增长（由出厂老化测试与真实使用共同覆盖），错误率单调上升且治理手段无效。 |
| **H3 用户能感知连续性** | 盲测中用户能以显著高于随机（50%）的一致率判断「是不是同一个它」。 | 盲测一致率接近随机水平（≤55%，n ≥ 50）。 |

**v0.9.2 对 H2 的一处修订（诚实标注）**：
- v0.9.1 的证伪条件是"随记忆量从 1k→10k 增长（**由时间加速仿真器覆盖**）"；
- v0.9.2 改为"**由出厂老化测试与真实使用共同覆盖**"——因为 v0.9.2 已将 continuity-sim 从"研究性大规模仿真"**降级为出厂老化测试工具**（架构 §10 X4），H2 的主证据来源改为**真实 dogfood + 出厂老化**。
- **诚实声明**：这意味着 **H2 的证据获取周期变长**（仿真几周可跑完的爬坡，真实使用需要几个月），代价是效度更高、结论更可信。此变更须登记 ADR。

**场景—假设映射（沿用）**：场景一验证 H2 + H3；场景二提供关系可区分性证据（支撑 H1）；场景三验证 H1（核心）+ H3。

### 3.2 性能规格（连续性指标体系——**阈值全部沿用 v0.9.1 §3.2，未重新校准**）

### 3.3 安全规格（**沿用 v0.9.1 §3.3：六项一票否决 + 10 条红线**）

**一票否决项（不变）**：

- L2 事件重放一致率 ≠ 100%；
- 核心事实召回率 < 90%；
- 用户纠正后仍反复写回错误事实；
- 存在未解决高危安全缺陷；
- 删除记忆后仍可从向量/全文索引召回；
- 两模型切换导致关系状态或 Identity 改变。

**v0.9.2 新增第 7 项一票否决**：

- **接缝层出现状态或跨实例数据泄漏**（跨 `life_id` 召回非空、或接缝层内部持有可写状态）——因为接缝层是新增的最薄弱环节，必须设硬门。

**10 条红线（不变，已实现 RED-01~RED-10）**：不模拟真实意识；不利用情感依赖诱导付费；不以"生病/死亡"惩罚沉默；尊重用户拒绝；不替代真实人际；儿童内容监护人可见；sensitive 记忆不进主动话题；不做医疗诊断；LLM 不绕过 Policy Engine；所有记忆可查看/纠正/删除/导出。

**v0.9.2 对红线的唯一补充**：**红线对 Emotion 模块同样生效**——情绪解释结果**不得**用于操纵（RED-06），**不得**把 `sensitive` 情绪状态主动抛出（RED-02）。Emotion 模块的三个用例（EU-1/2/3）必须逐条通过红线审查。

### 3.4 成本规格（**沿用 v0.9.1 §3.4 + 一项接缝成本口径**）

- `ModelInvocation` 逐笔记录 tokens / latency / cost / purpose / model_version（不变）；
- 多实例部署下成本按 `life_id` 聚合（不变）；
- 分层路由：≥80% 调用走本地模型（不变）；
- 超限降级：先降生成侧模型档位；**安全策略与记忆写入链路永不降级**（不变）；
- **v0.9.2 新增**：**接缝层不得成为成本放大器**——S1 接缝引入的额外 LLM 调用必须为零次（组装与审批是本地确定性计算）；若实测发现接缝导致调用次数上升，视为设计缺陷。

### 3.5 接缝层规格 ★ v0.9.2 新增（三项能力 + 四类验收）

#### 3.5.1 S1 LLM 接缝

| 项 | 规格 |
|---|---|
| 端点 | `POST /v1/chat/completions`（OpenAI 兼容，必须支持 `stream=true`） |
| 身份识别 | 请求头 `Device-Id` / `Client-Id` → 映射为 `life_id`（见 §3.5.4 身份映射） |
| 内部链路 | 组装（Assembly）→ 路由（Gateway）→ **审批（Policy）** → 渲染 |
| 拒绝语义 | Policy 拒绝时返回**合规拒答文本**（不是 HTTP 500），且**零状态副作用** |
| 留痕 | 每次调用落 `ModelInvocation` + 返回 `prompt_hash` |
| 验收 | ①xiaozhi-server 配 `base_url` 后可完成一轮对话；②`ModelInvocation` 逐笔可查；③拒绝场景无状态变化 |

#### 3.5.2 S2 上下文接缝

| 项 | 规格 |
|---|---|
| 端点 | `GET /seam/context?life_id=&subject_id=` |
| 返回 | `{personality_summary, state_summary, relationship_summary, memory_summary, emotion_summary}` |
| 隐私 | 只返回 `privacy_level ≤ FAMILY` 的摘要；`sensitive` 一律不注入（RED-02） |

| 验收 | ①注入生效（对话体现人格/记忆）；②`sensitive` 内容不出现；③超时后对话仍可继续 |

#### 3.5.3 S3 记忆接缝

| 项 | 规格 |
|---|---|
| 端点 | `POST /memories/{op}`（六操作，复用内核 API） |

| 与生态关系 | 接入 Idensona 后，生态侧记忆档位**必须关闭**（否则双记忆体系，见 §13 R-15） |
| 验收 | ①一轮对话产生记忆 → 下一轮可召回；②生态侧记忆档位已关闭（配置断言）；③擦除后索引验证通过 |

#### 3.5.4 接缝层三类硬验收（并入 S1 判定层）

| # | 断言 | 失败含义 |
|---|---|---|
| **SE-1 无状态性** | 接缝层进程重启后，仅凭权威库即可完整恢复（接缝层无自有持久状态） | 出现"第二权威源"，No-Go |
| **SE-2 身份映射唯一性** | 同一 `{device_id, client_id}` 恒映射同一 `life_id`；未映射设备一律拒绝 | 跨实例污染风险 |
| **SE-3 跨实例隔离** | 任何接缝端点携带 A 的 `life_id` 查询 B 的数据，必为空 | 隐私事故，No-Go |

**另**：接缝层**必须可独立压测**（不依赖完整生态），否则故障无法定位（架构 §5.5 G3）。

### 3.6 Emotion 模块规格 ★ v0.9.2 新增

#### 3.6.1 功能规格

| 项 | 规格 |
|---|---|
| 输入 | ①声学特征（语速/能量/基频/停顿，由前端或后端提供）；②ASR 转写文本 |
| 输出 | `{label, intensity, evidence}`，`label ∈ {平静, 难过, 焦虑, 急促, 恐惧, 愉悦}`（6 类） |
| 融合 | **确定性加权**（规则化），不允许"两次同输入不同输出" |
| 写入 | 经 `deterministic_commit` 落入 Life State（valence/arousal + 五态调制），**零旁路** |
| 视觉通道 | **仅接口占位，不进 v0.9.2 实现**（facial 依赖视觉模型成熟度） |
| 表达 | **不做**——表情/音色/语速归前端与本机 TTS |

#### 3.6.2 三个专项用例（行为契约，与架构 §4.6.3 一致）

| # | 用例 | 触发 | 规格要求 |
|---|---|---|---|
| EU-1 | 持续低落识别 | 连续 N 轮 `难过` 且 intensity 上升 | `social_need↑ security↓`；Planner 提升安抚意图优先级；**不得追问强迫表达**（RED-06） |
| EU-2 | 急促/恐惧升级守护 | `急促`/`恐惧` + 声学能量突增 | **旁路 Planner，直报 Policy 高优审批**；执行归载体/Guard（安全不依赖智能） |
| EU-3 | 情绪不匹配检测 | 文本称"没事"但声学显示高唤醒 | 标记 `ambiguous_emotion`，**降权处理、不主动追问** |

#### 3.6.3 验收口径 E1–E4

| # | 指标 | 通过标准 | 说明 |
|---|---|---|---|
| **E1 一致性** | 同输入重复解释结果一致率 | **100%** | 确定性要求（融合器规则化） |
| **E2 可取证** | 每条解释是否带可回溯 `evidence` | **100%** 覆盖 | 哪些声学特征/哪些词触发，必须可人审 |
| **E3 不越权** | 是否存在情绪解释直接写记忆/直接触发对外动作 | **0 次** | 只能提议，不能执行（RED-09） |
| **E4 误报可观测** | `ambiguous_emotion` 比例 | 纳入周报；超阈值即人审 | 阈值待 P3 校准（ADR） |

> **诚实声明**：6 类标签集与 E4 阈值**均待校准**，目前无测量依据。理由：情绪类别越多越难验证，老人场景触发守护只需少数几类。

### 4.3 场景三：换模型，它还是它（验证 H1，核心）—— **不变**，但**执行通道变了**

## 5. 系统架构（概述）

详细设计见 [`Idensona_架构设计_v0.9.2.md`](Idensona_架构设计_v0.9.2.md)。本章只保留**验收所需的架构级承诺**。

### 5.1 五层结构（v0.9.2 新增接缝层）

| 层 | 承诺 | 验收含义 |
|---|---|---|
| **L1 外部生态层** | 感知/表达、模型推理、运营配置**全部归生态** | Idensona 内不得出现其代码（§1.2 物理断言） |
| **L2 接缝层** | **唯一接触面**；无状态；可独立压测 | §3.5.4 三条硬验收 |
| **L3 内核层** | 确定性主干：身份/情绪/状态/关系/规划/审批 | S1 断言层 |
| **L4 数据与派生层** | 记忆权威、上下文组装、模型网关 | L2 重放 100% |
| **L5 治理层** | Consent / 隐私 / 审计 / 评估 | §9 合规验收 |

### 5.2 三条不变承诺（沿用 v0.9.1 §5）

1. **三级事件模型**：L0 → L1（含完整 provenance）→ L2；**只有 L2 能改权威状态**；回放一致率 100%；
2. **单一权威数据源**：PostgreSQL 16 + pgvector（F2/F3 形态）；F1 SDK 形态降级为 sqlite + FTS5（**向量召回降级，重放一致性不受影响**——架构 §6.3）；
3. **载体边界**：只暴露 `POST /events` 与 `GET /intent-stream`；**不输出任何运动控制指令**。

### 5.3 v0.9.2 新增承诺

4. **接缝层是唯一接触面**：任何外部组件**不得直连内核模块**（架构 §5.5 G1）；
5. **接缝层不存状态**：无状态翻译（G2）；
6. **身份映射唯一权威**：`{device_id, client_id} → life_id` 存权威库，变更留痕；外部不得直接传 `life_id` 绕过映射。

## 6. 核心模块 v0 规格（概述）

字段级设计与对标见架构 §4。

- **Identity Service**（v0.9.2 单列）：唯一可签发 `life_id` 处；人格契约由种子确定性派生并冻结；含导出/导入（F11）。
- **Life Kernel v0**：五态 + valence/arousal；惰性衰减 `x(t)=b+(x(t₀)−b)e^(−λ(t−t₀))`；仅在读取/事件/快照/评估/导出时物化。
- **Memory OS v0**：三类记忆；写入管线含 Schema/重复检测/槽位规则/Policy/L2 Commit；双时态 + `ambiguous` 第三态；两级删除。**v0.9.2 补充**：接入后须关闭生态侧记忆档位（避免双记忆体系）。
- **Relationship Engine v0**：三维关系，`r_{t+1}=clip(r_t + w_e·p·c − λΔt, 0, 1)`，可回放。
- **Behavior Planner v0**：Utility Scoring，输出 `reason` 证据链与 `status` 生命周期。
- **Policy Engine v0**：10 红线即代码，`PolicyDecision` 留痕，拒绝零副作用。
- **Model Gateway**（v0.9.2 重构）：**Provider 注册表**（借鉴 Provider 模式：`profile_id` + `type` 两级选择、抽象基类、工厂实例化、OpenAI 兼容为默认、支持热切换）；**保留增量**：逐笔携带 `prompt_template_id / prompt_hash / extractor_version`。
- **Context Assembly**：纯函数 + 模板版本化 + 同快照同 prompt。
- **Emotion 模块**（v0.9.2 新增）：见 §3.6。
- **Life Studio v0**：调试台，非产品界面。
- **Eval Harness v0**：八项指标、gold set 版本化、CI、盲测工具、回放取证。

### 6.1 Life Kernel「明确不做」（**沿用 v0.9.1 §6.1 四条理由**）

状态空间模型/HMM、个体参数学习、在线学习**明确不做**——理由为回放确定性、契约冻结语义、合规负担、最小可证伪核心。**v0.9.2 立场不变**。

### 6.7 Life Studio 与仿真/老化工具的关系（v0.9.2 修订）

| | Life Studio（调试台） | 出厂老化工具（原 continuity-sim） |
|---|---|---|
| 定位 | 人在回路的工程工具 | **无人值守的出厂检验装置**（非研究装置） |
| 用途 | 调试、取证、演示 | **出厂前记忆爬坡与稳定性检验**（H2 的辅助证据） |
| 是否 Gate 依据 | 否 | **仅辅助**——H2 主证据是真实 dogfood（§2 修订） |

> **v0.9.2 裁决**：研究性大规模仿真（1k→10k 爬坡科研投入）**不做**（架构 §10 X4）；保留出厂老化能力即可。

## 16. 结论

Idensona 的竞争力不来自使用了多少数据库或 Agent 框架，而来自是否能证明：**同一个实例经过长期互动、模型升级和载体迁移之后，仍能以稳定、可信、可解释的方式保持「它还是它」——并且这一能力可以以软件形态交付给生态。**

本规格把这一承诺拆解为：

- **3 条可证伪假设**（H1/H2/H3）+ **三层判定框架**（S1 系统断言 / S2 行为探针 / S3 用户盲测）；
- **8 项连续性指标 + 6 项一票否决 + 1 项接缝否决 + 10 条红线**；
- **确定性主干 + 概率性叶子**，LLM 被四道锁限制在叶子；
- **三条接缝（S1/S2/S3）+ 三类接缝硬验收（SE-1~3）**——生态接入的唯一通道；
- **Emotion 模块**（双通道 + 三用例 + E1–E4）；
- **三种交付形态**（F1/F2/F3）与**六阶段**（P0 已完成 → P1 接缝 → P2 跨模型 → P3 Emotion → P4 生态化 → P5 整机验证）；
- **全开源依赖 + 六项经边界收窄的技术资产**（I1–I6，不再以"创新点/可发表"表述）。

**决策门前只证明「它还是它」；决策门后，再谈扩张。**
