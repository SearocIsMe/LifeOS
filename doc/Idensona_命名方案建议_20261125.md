# Idensona 命名方案建议（2026-11-25，2026-11-26 定名）

> **命名状态：已定名 ✅** —— **Idensona = Identity + Persona**（域名 `idensona.com` 已注册到手）。
> 自本日起，项目正文统一使用 **Idensona**；`LifeOS` 降级为**项目历史代号**（历史版本文档 `LifeOS_*_v0.9.1.md` 保持原名不改，以保留版本可追溯性）。
>
> **背景（原始命题）**：`LifeOS` 域名已被注册，需要一个能涵盖"软件内核"实质、且可长期用于生态与商业合作的名称。本文记录完整的命名推演过程与最终选择依据。
> **诚实声明**：本文**不判断任何域名是否可注册**——作者无法执行 whois 查询，任何"这个域名还空着"的结论都属编造。文中候选的可用性均须你自行核验（§5 核验清单；实际核验结果已见下方"核验结果"）。
>
> **命名依据**：名称必须覆盖 v0.9.2 架构的**七个一等资产**（Identity / Life State / Memory / Personality / Relationships / Development History / Behavior Policy）与**一个差异化命题**（换模型换设备后仍是同一个它 + 可回放取证）。

## 1. 先明确"名字要承载什么"（命名约束）

| 约束 | 说明 | 反例（应避免） |
|---|---|---|
| C1 **不能只覆盖"生命/寿命"** | `Life*` 系列已被大量占用（Life360、LifeMD 等），且语义偏"健康/生活服务" | `LifeCore`、`LifeKernel` |
| C2 **不能只覆盖"记忆"** | 会退化成 Mem0/Letta 的同类定位，丢掉身份连续性 | `MemoryOS`、`MemoCore` |
| C3 **不能只覆盖"人格/陪伴"** | 会被误认为角色聊天产品（红海） | `PersonaOS`、`CompanionCore` |
| C4 **要能说清"模型之外"** | 名称最好隐含"不依赖模型/可迁移" | `LLMLife`、`ModelLife` |
| C5 **要能扩展到生态** | 未来有 SDK、云服务、合规包等子品牌 | 过于具体的技术名词（如 `PGVectorLife`） |
| C6 **发音与拼写要稳** | B 端合同、口播、搜索都需要 | 生僻拉丁词根（如 `Quiddity`） |

> **一句话**：名字应表达"**同一个它**"（sameness through change），而不是"更多记忆"或"更像人"。

## 2. 三条命名路线（各有取舍）

### 路线 A：拉丁/希腊词根（短、可注册性相对好、语义精准）

| 候选 | 词源与含义 | 为何贴合 | 风险 |
|---|---|---|---|
| **Idem** | 拉丁 "the same"（同一） | **最精准**：直指"换模型还是同一个它"；极短，易做品牌 | 过于抽象，需配副标（如 `Idem — identity continuity kernel`）；单词型域名大概率已被占用 |
| **Eadem** | 拉丁 "the same"（阴性形式） | 同上，更少见、可注册性略高 | 认知门槛（多数人不认识） |
| **Constare** | 拉丁 "to stand firm / remain consistent" | 表达"持续一致"，兼顾状态稳定性 | 拼写较长 |
| **Mneme** | 希腊 "memory"（记忆女神 Mnemosyne 的词根） | 覆盖记忆但**不限于检索**，带"记忆是身份的一部分"意味 | 可能被理解为纯记忆产品（触 C2） |
| **Anima** | 拉丁 "soul / life principle" | 表达"内在性"，与外部形象解耦 | 已被大量游戏/心理类产品使用 |
| **Perdurare** | 拉丁 "to endure / persist through time" | 直指"跨越时间仍在" | 过长 |

**路线 A 组合建议**（把核心词 + 功能后缀，提升可注册性）：

- `idemcore` / `idem-kernel`
- `mnemecore` / `mneme.io` 类
- `constare.dev`

### 路线 B：功能直述（最好解释、最好卖，但可注册性差）

| 候选 | 含义 | 为何贴合 | 风险 |
|---|---|---|---|
| **Continuum** | 连续体 | 直指"连续性"，是七资产的总纲 | 通用词，域名/商标拥挤 |
| **Continuity Kernel** | 连续性内核 | 与架构术语完全对齐，B 端一听就懂 | 太长，只宜作副标 |
| **Identity Kernel** | 身份内核 | 直击核心 | 偏窄（丢记忆/关系/情绪） |
| **Provenance Core** | 溯源内核 | 突出"可回放取证"这一护城河 | 偏技术，C 端无感 |
| **Anchor** | 锚 | 生态隐喻极佳（生态可变，锚不变） | 通用词，占用严重 |

**路线 B 组合建议**：

- `anchorlife`（锚 + 生态，注意仍含 life）
- `continuumcore`
- `identitykernel.dev`

### 路线 C：隐喻/品牌化（最好记、最易做商标，但需解释成本）

| 候选 | 隐喻 | 为何贴合 | 风险 |

| **Keel** | 龙骨（船的稳定结构） | "生态在变，龙骨不变"——极精准的架构隐喻 | 隐喻较隐晦 |

| **Tether** | 系绳 | 表达"关系不断的连接" | 可能被误解为网络/加密产品 |
| **Stele** | 石碑（铭刻不灭） | 表达"记忆铭刻、不可篡改" | 生僻 |

## 7. 中文词根路线（2026-11-25 增补：Idem/Mneme 已被注册后的替代）

> **为什么中文词根是更好的方向（不只是"退而求其次"）**：
> ① **语义密度高**——一个汉字能承载"变中之不变"这类完整命题，拉丁词根需多词组合；
> ② **撞名概率低**——中文拼音转写串在域名库的密度远低于 `idem`/`mneme` 这类短词根；
> ③ **战略匹配**——首发中文社区（四法域中文兼容），中文词根对 B 端沟通零翻译损耗；
> ④ **有真实古典出处可讲**——「恒」（《易·恒卦》）、三易之「不易」、「复命曰常」（《老子》）都能讲成产品叙事，而非硬凑。

### 7.1 核心候选（按"贴合度 × 撞名风险"排序）

| 候选 | 中文 / 出处 | 语义为何精准贴合 | 撞名风险（已知） |
|---|---|---|---|
| **不易**（BUYI） | 《易》三易：**变易 / 简易 / 不易**（"不易"= 不变的那部分） | **叙事最佳**："万物皆变易，唯此不易"——完美对应"模型在变，身份不变" | 🟢 低（非日常词）；但**同音"布衣"**需查（N-1） |
| **恒**（HENG） | 《易·恒卦·彖》"恒，久也"；"不恒其德，或承之羞" | **最精准**：直指"跨越时间仍是它"；单字品牌力强 | 🟡 中（超高频字，须组合） |
| **常**（CHANG） | 《老子》十六章"复命曰常"；佛典"常乐我净" | 与"无常"对举的"恒常"，哲学味足 | 🟡 中（高频字） |
| **守**（SHOU） | 道家"守一"；日常"守护" | 直指"守住记忆与身份"，情感温度最高 | 🟡 中 |
| **铭**（MING） | 铭刻 / 铭记 | 记忆不可篡改的隐喻（对应 provenance、append-only） | 🟡 中（科技品牌已见） |
| **贞**（ZHEN） | 《易》"贞固"、"贞者事之干也" | 表达坚定不改变 | 🟡 中（多义：贞洁，易歧义） |
| **不迁**（BUQIAN） | "迁"= 变更；《易·系辞》"不迁怒"（**此处语义偏"不转移怒气"，易误读**） | 字面"不因迁移而改变"很对位 | 🟢 低，但**出处例句有歧义，不推荐首选** |

> **诚实提示**：`不易` 的口语义是"不容易"，需靠副标固定（如 `BUYI — the unchanging part`）；但正因如此记忆点强。`不迁` 虽字面对位，古典例句语义有歧义，**不建议作主名**（列出仅求完整）。

### 7.2 推荐组合（规避单词型占用，`heng`/`chang`/`shou` 单词域基本不可得）

| 组合 | 含义 | 说明 |
|---|---|---|
| **buyi / buyi-id / buyi.dev** | 不易 | 叙事最强，转写短，撞名风险最低 ★首选 |
| **bu-yi** | 不易 | 加连字符增强商标区分度与辨识 |
| **henglab / hengcore** | 恒 | 直白好拼，品牌力强 |
| **changzhu（常驻）** | 常 + 驻（持久存在） | **语义极佳**："常驻不退"，技术圈一听就懂 |
| **shoucore** | 守 | 守护内核；可与英文 `Keeper` 形成中外双轨 |
| **minglu（名录）/ mingkee** | 铭 + 录 | 暗合"事件记录 + 可回放" |
| **hengjiu（恒久）** | 恒久 | 可读性最好，但语义偏泛（缺"身份"指向） |
| **bubian（不变）** | 不变 | 极直白，撞名风险中 |

### 7.3 三档推荐（中文词根版）

| 档 | 候选 | 为什么 |
|---|---|---|
| **第一档** | **BUYI（不易）** | 古典出处精准（三易之"不易"）+ 叙事独一无二（"万物变易，唯此不易"）+ 转写短、撞名风险低。副标：`BUYI — the unchanging part` / `不易 · 变中之不变` |
| **第二档** | **HENG（恒）→ hengcore** / **CHANGZHU（常驻）** | 「恒」单字品牌力最强；「常驻」把"持久存在"讲得最白 |
| **第三档** | **SHOU（守）** / **MING（铭）** | 情感向与不可篡改向各占一端，**更适合做子品牌**（如量尺取证包用「铭」→ `Ming Proof`） |

### 7.4 中文词根特有的风险与核验项

| # | 风险 | 说明 | 处置 |
|---|---|---|---|
| N-1 | **同音词冲突** | `buyi` 同音「布衣」——既有词汇且文化含义强，可能已在同类目注册 | 先查「布衣」商标；或用 `bu-yi`、`buyi.id` |
| N-2 | **超高频拼音** | `heng`/`chang`/`shou` 极常见 | **必须走组合**，单词型放弃 |
| N-3 | **海外解释成本** | 中文词根对海外客户需解释 | 用英文副标承载语义 |
| N-4 | **中文商标类目** | 软件（第 9 类）、SaaS（第 42 类）需**分别**检索 | 并入 §5 V2 并扩大到这两个类目 |
| N-5 | **古典出处考证** | 本文引用的《易》《老子》表述为**通行理解，未逐版本校勘** | 对外宣传引用原文前请再核一次 |

> **出处可靠性声明**：§7.1 的「恒，久也」（《易·恒卦·彖》）、「复命曰常」（《老子》十六章）、三易「变易/简易/不易」（传统说法，多见于《易纬·乾凿度》一类文献）均为**通行理解**；本文未做逐版本校勘，用于对外叙事前建议核对原文。

### 7.6 一句话（§7）

**中文词根里最贴合"变中之不变"的是「不易」（BUYI，出自三易）——叙事比 Idem/Mneme 更强、转写更短、撞名风险更低；次选「恒」（hengcore）与「常驻」（changzhu）；落地前必须先查"布衣"同音商标与第 9/42 类中文商标，并对古典出处做一次原文核对。**

> **注（2026-11-26）**：§7 的推演已完成其使命——最终定名为 **Idensona（Identity + Persona）**，未采用中文词根方案。本节保留为**命名决策的完整记录**（说明"为何最后选了英文复合词而非中文词根"：Idensona 同时覆盖 Identity 与 Persona 两个核心资产，语义完整度高于任何单一词根）。

## 8. ⚠️ 定名后的语义风险：Persona ≠ 角色扮演（必读）

**这是 Idensona 这个名字唯一的实质性风险，必须在所有对外材料中处理。**

| 维度 | AI 行业对 "Persona" 的常见理解 | **Idensona 的 Persona 含义** |
|---|---|---|
| 所指 | 可切换的角色人设 / 提示词扮演（如"今天扮演傲娇女友"） | **长期稳定、版本化、冻结的人格契约** |
| 可变性 | 随时换 | **生成后冻结**，变更须走 ADR |
| 承载物 | system prompt 文本 | `PersonalityContract` 实体（大五参数 + 表达风格 + 冻结时间） |
| 是否可回放 | 通常不可 | **可回放重算**（同种子必得同参数） |

### 8.1 对外表述纪律（三条）

| # | 纪律 | 反例（禁止使用） |
|---|---|---|
| P-1 | **必须区分"人格契约"与"角色扮演"** | ❌ "Idensona 支持多种人格玩法" |
| P-2 | **强调"冻结 + 版本化"** | ❌ "随时切换人格" |
| P-3 | **中文对外统一用「人格契约」，不用「人设」** | ❌ "Idensona 的人设系统"（"人设"在中文语境= 可扮演的角色设定） |

### 8.3 Idensona 定名术语表（文档与代码的一致性基准）

| 对外名称 | 内部术语 | 代码现状 | 是否改名 |
|---|---|---|---|

### 8.2 与竞品文档红海判断的一致性
